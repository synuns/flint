# flint 테스트 작성 규약 (v0.20.2 —)

패치 루프 테스트 품질 감사(3축: 계약 커버리지·무의미/왜곡·구조화)에서
도출된 규약. 신규 테스트 작성 시 지킨다.

## 1. 파일·네이밍

- 신규 테스트는 **기존 명령/주제별 파일에 추가**한다(read 관련이면
  read_test.go, 스키마 게이트면 admin_test.go) — 버전은 테스트 주석에
  표기(`v0.20.2: …`). `*_v0XXX_test.go` 신규 생성 금지(기존 70%가 버전
  접두 파일로 흩어진 전례 — 같은 계약이 여러 파일에 중복됨).
- 문서 회귀는 docs/versions_test.go의 표에 행 추가로 끝낸다(v0.20.2
  통합 — 버전별 파일 재증식 금지).

## 2. fixture 라우팅(queryFn)

- 미매칭 쿼리를 조용히 흡수하는 폴백 금지 — `t.Fatalf`로 계약 위반을
  드러낸다(제품 쿼리 추가 시 fixture가 잘못된 데이터를 주던 왜곡 방지).
- 판별은 좁고 고유한 형태로. 제품 SQL과 공진화하는 substring 추측이
  불가피한 쿼리는 제품 SQL에 자기 식별 마커(`/* stale */`)를 둔다.
- fakeStore 파생형은 기존 변형(readEventRecorder·dupMetaStore 등) 재사용
  우선 — 이름이 의도를 드러내는 한 통합하지 않는다.

## 3. 단언

- 테스트는 **계약(기획)을 단언**한다 — 구현을 복창하지 않는다. 기대값은
  리터럴로 고정(구현 함수 호출로 want를 생성하면 그 함수가 틀려도 통과).
- 깨진 동작을 "계약"으로 문서화하지 않는다 — 전례: store-free setup이
  항상 degraded인 결함을 테스트가 '계약'이라 부르며 고착(v0.20.1 F2).
- 강등·폴백 경로 테스트는 강등 조건을 실제로 만들어 검증(에러 주입·
  경계 데이터) — 정상 경로의 우연한 통과로 대체 금지.

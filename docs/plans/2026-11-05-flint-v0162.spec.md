## 3. 요구사항

### R1 드릴 계약 완결 (리뷰 ①②③)
- dropDrillDB: DROP 후 `pg_database` 조회로 잔존 검증 — no-op 시
  명시적 실패(기존 "잔존 숨기지 않음" 계약 회복). 재시도 소진 시에도
  잔존 보고.
- 지연 정리 DROP: `context.Background()` + 독립 짧은 타임아웃(30s) —
  재생 ctx 만료와 무관하게 항상 실행.
- tests/regression/drill_test.go: flint_drill 스키마 단얱 4곳 →
  `pg_database`의 flint_drill_db 부재 검사로 교체·죽은 DROP SCHEMA
  선행 정리 제거.

### R2 CI CREATE 가드 (리뷰 ④)
- flint_test 생성: 실패 출력에서 `already exists`만 허용 통과, 그 외
  실패는 exit 1(진단 위치 보존).

### R3 테스트 헬퍼 통합·검증 스크립트 정리 (리뷰 ⑤⑥)
- docs 패키지 공유 `docStr(t, path)` 헬퍼 1개로 통합(v0151~v0161
  파일들의 로컬 복제 대체 — 기존 테스트 함수 본문은 불변, 헬퍼 호출
  명칭만 승계 갱신 허용 룰링). flint-plugin 패키지 readV0160/0161 동일.
- validate_yaml: 매니페스트 파싱 결과 재사용(이중 로드 제거).

### R4 pending 만료 (관측+Mem0 Dream)
- `flint maintain --expire-pending <days>` — valid_at 경과 N일 초과
  pending 행 나열(dry-run 기본)·`--commit` 플래그 시 무효화(status
  pending→expired? 아니면 삭제?) — **설계 결정: 삭제 아닌 invalidated
  상태 전환**(valid_at·audit 보존, 스키마 불변 — status 값만 신규
  'expired'는 additive? 기존 status 열거 pending|active|invalidated에
  expired 추가는 읽기 경로--status 필터 영향. 단순화: 기존 invalidated
  재사용 + invalid_reason 메타? 가장 additive한 것: **삭제**가 아니라
  유지보수 경로에서 `status='invalidated'`+invalid_at=now 세팅 — 기존
  무효화 경로 승계, 신규 상태 없음).
- doctor pending-age 검사 갱신: 기존 임계 안내에 만료 명령 안내 추가.

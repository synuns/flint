# flint v1.1.0 스펙 — 토큰 관측(바이트 계측)·마일스톤 잔여

- 날짜: 2026-11-13. 원칙: additive 스키마·개인정보 무수집(바이트 수만 —
  본문 미기록)·동작·출력 불변(신규 필드는 additive).

## 1. 토큰(바이트) 관측 — 핵심 가치의 계측

PLAN 요구사항 2 "토큰 최적화 검색 — 필요한 최소 바이트만 컨텍스트
진입"이 지표로 없었다(도움 G1~G4는 횟수만). G5 신설:

- **G5 최소 주입** — 컨텍스트에 들어간 바이트가 예산 안에서 최소인가.
- 신호: 세 표면의 실제 출력 바이트(UTF-8 rune 수 아닌 바이트 길이).
  1. `read` — FormatRows 출력 길이(제로히트 무출력=0).
  2. `hot`(주입) — ClampHot 절단 '후' 최종 출력 길이(예산 준수 실측).
  3. `brief` — ClampHot 절단 후 길이(기기 밖 유출량 관리).
- 저장: daily 카운터 신규 키 `read_bytes`·`hot_bytes`·`brief_bytes`
  (기존 daily:<date> JSON 증분 — 스키마 무변경). 원시 이벤트 테이블
  확장은 불필요(평균 = bytes/호출수, 분포가 필요해지면 그때).
- 보고: report effect에 `bytes` 객체 — read/hot/brief 각 `bytes_14d`·
  `avg_bytes`(호출당 평균). status에 `hot_bytes_14d`(주입 예산 실측 —
  hot_budget 준수 감시). METRICS.md §2 G5 행·§4 지표 정의 추가.
- 집계 원칙: 횟수 지표와 동일 보존창(daily 14일) — 분산 계산 없음.

## 계약

### 스키마 v13 (additive — EnsureSchemaV13 1개에 전부)

1. `read_events` 열 확장: `near_score double precision NOT NULL
   DEFAULT 0` — **zero 행 전체(near 무관)에 스캔 최고 bigramDice 점수
   저장, 히트 행=0**. min_score 경계 아래 분포가 C1 what-if
   (§12.2 분류층 counterfactual — 예: 0.15→0.1 하향 시 near 전환 행)의
   핵심 대상이므로 near=false 행을 0으로 마스킹하지 않는다. 쿼리 본문
   비저장 원칙(schema.sql:85-87) 승계 — 점수만.
2. 신규 `threshold_snapshots(ts timestamptz NOT NULL DEFAULT now(),
   key text NOT NULL, old_value text NOT NULL, new_value text NOT
   NULL)` append-only + `CREATE INDEX … ON threshold_snapshots
   (key, ts DESC)` — "직전 스냅숏" 키별 최신 행 조회가 전체 스캔되지
   않게. 임계값 diff-on-write. 동기(fired 캡처) 열은 B3 등록표
   시점(v1.23.0)으로 이월.
3. 신규 `weekly_rollups(week_start date NOT NULL, metric text NOT NULL,
   num bigint NOT NULL, den bigint NOT NULL, PRIMARY KEY (week_start,
   metric))` — 분자·분모 카운터만 저장(파생 비율 금지 — Prometheus
   집계 관례). metric: `zero_pct`·`fallback_pct`·`pair_pct`(분자·분모
   정의는 ops/report.go:117-127 준용, METRICS.md가 단일 소스).
4. 게이트 체인: schema_gates.go 레지스트리 1행·LatestSchemaVersion
   12→13·schema.sql 신규 생성 경로에 v13 종착상태 반영. 열 확장은
   DEFAULT 포함 ALTER(v11 선례 admin.go:502-513 — 이전 바이너리
   호환)·기존 열 변경 금지.
5. 계측 커밋: 테이블 2종을 telemetryStageTables·(serial 채택 시)
   telemetryStageSeqs에 명시 추가 — 전역 dolt_add 금지 준수.

### 적립 회로 (독립 롤오버 — maybePruneAfterRead 패턴 복제)

- **A1**: SuggestSimilar가 min_score 필터 **이전**의 스캔 최고치
  (scanMax)를 함께 반환(반환 형태 — 결과 엔벨로프 필드 또는 별도
  반환값 — 구현 선택, Suggestion 하위 k와 독립). read 경로가 이를
  RecordReadEvent에 전달, INSERT 열 1개 추가(왕복 +0). 근거: 현행
  SuggestSimilar는 min_score 미만 행을 반환 전에 버림(suggest.go:
  154-157)·상위 3의 ID·Topic만 반환(:171-174) — 스코어 폐기 지점.
- **A2** (훅 위치: RecordReadEvent 뒤 — read 명령 흐름 내
  maybePruneAfterRead 패턴): 1일 1회 게이트(meta
  `last_threshold_snapshot_at` RFC3339 + 프로세스 내 1h 캐시). 만료 시
  LoadThresholds 전체 키 로드 — 직전 스냅숏과 비교, 변경 행만 append.
  **최초 만료(테이블 빈 상태) 시 전체 키 시딩** — 이후 변경분만.
  실패 조용히. read 없는 날 공백은 1일 게이트가 따라잡음(다음 read 시
  만료분 일괄 처리).
- **A3** (훅 위치: A2와 동일 — read 흐름 내): 동일 패턴(게이트
  `last_rollup_at`). 지난 주[UTC 주 경계·PruneDaily 자정 롤오버
  관례 승계] raw 이벤트에서 num·den 집계 후 UPSERT — raw에서 재생성
  가능한 캐시(멱등). **순서 보장 = A3 롤오버가 PruneReadEvents(보존
  만료 삭제)보다 선행** — 동일 흐름에서 집계 확정 후 만료 삭제.
  놓친 주는 소급 없음(2주 연속 read 부재 시 해당 주 rollup 소실 —
  극단 조건이며 C1 소비에 치명적 아님).
  events_*_retention_days 오버라이드 <8일이면 주 완전성 보장 불가 —
  TUNING §2에 상호의존 주석(경고는 아니고 문서 계약).
- **왕복 예산 ≤5(§12.4)**: A2 = 게이트 SELECT 1 + 임계값 로드 SELECT 1
  + 직전 스냅숏 SELECT 1 + INSERT N(변경분만). A3 = 게이트 SELECT 1 +
  집계 SELECT 1 + UPSERT N. 하루 1회 경로라 예산 내.
- **PruneDaily 편승 기각**: recordWithRetry 롤오버 훅은 첫 쓰기에만
  걸림 — write 없는 날 적립 생략 결함(usage.go:441-449 롤오버 훅·
  :82-85 PruneDaily 롤오버 설명).

### 경고 (무저장)

- **A4 계측 신선도**: doctor 등록표 1행 `metering-freshness`(ThFn 주입형

- **A5 커버리지**: 관측 키 등록 3곳(usage.go:101 intake 10종·
  approve.go:49 curation 11종 — RecordUsageCount kind와 별개 전용 키
  공간 계약(approve.go:46-48)·usage.go:152 bytes 3종)을 **집합 구분을
  유지하는 통합 레지스트리**(그룹별 슬라이스/맵 — flat 병합 금지)로
  통합 후 diagnose가 등록 대비 장기 미발화 차집합 경고 — 등록표 기반
  (Prometheus absent() 관례). 합집합 24키 동질 가드 동반.

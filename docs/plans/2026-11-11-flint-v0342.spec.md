## 1. 코드 결함 2건

### 1.1 (R1) tuning 관리 키 3중 유지 — backup_encrypt 드리프트 [높음]

- `tuning set backup_encrypt true`는 동작(등록: lib/cli/tuning.go:103).
- 그러나 `tuningCurrent`(tuning.go:191)와 `tuningResetAll`(tuning.go:401)의
  하드코딩 all 목록(6키 리터럴, 2곳 복제)에는 이 키가 없다.
- 증상: set 직후 `tuning list`는 `override:false` 거짓 보고 ·
  `tuning reset --all`이 이 오버라이드를 삭제하지 않는다.
- 수정: 두 인라인 목록을 `tuningMetaKeys()`에서 파생한 단일 헬퍼로 교체.
  thresholdsKeys↔tuningKeys 동질 테스트(maintain.go:1041 관례)와 같은
  드리프트 가드를 meta 키 계열에도 부여.

### 1.2 (R2) usage 문장 하드코딩 — pending 누락 [중간]

- lib/cli/registry.go:34 usage 문자열이 등록 24커맨드와 수동 동기되어
  v0.29.0 신규 `pending`이 누락(23개 나열).
- 수정: usage 문장을 레지스트리에서 생성. 표시 순서 슬라이스(usageOrder)
  + "usageOrder 집합 == registry 키 집합" 동질 테스트로 영구 가드.
  신규 커맨드는 Register만 하면 usage에 자동 반영.

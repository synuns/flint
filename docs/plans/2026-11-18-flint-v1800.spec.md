# flint v1.8.0 스펙 — Doltgres 방언 절단 (Store 히스토리 인터페이스)

## 배경

v1.7.0 종속도 조사(#31971): dolt 방언(dolt_log·dolt_diff·
dolt_commit_diff_knowledge·AS OF)이 lib/db 밖 7개 파일에 흩어져
호출층이 원시 SQL로 엔진을 직접 의존. 사용자 지시로 DB 절단을
v1.8.0 1차 과제로 확정(이후 다중 기기 안정화 v1.9·스코프C/v2.0).

## 필수 요구사항

1. **Store 히스토리 인터페이스**: wire.Store에 개념 수준 5메서드
   추가 — `LogEntries(ctx, LogQuery)`·`QueryAsOf(ctx, AsOfQuery)`·
   `DiffRows(ctx, from, to)`·`DiffStat(ctx, hashes)`·
   `DiffCommits(ctx, from, to)`. 시그니처는 SQL이 아니라 커밋·시점
   질의 개념을 표현(PG 동등 구현 길 확보).
2. **db 패키지 폐쇄**: lib/db가 유일한 방언 소유지. 호출층
   (wire/asof·knowledge/read·ops/status·audit·diff)은 전부
   Store 메서드 호출로 전환, 원시 dolt SQL·AS OF 인라인 제거.
3. **동작 불변**: 순수 리파터링 — CLI 출력 바이트 동치(audit·
   diff·status·read --as-of 포함). 오류 경로·exit 코드 계약 유지.
4. **방언 폐쇄 게이트**: Go 테스트로 lib/db 밖 `dolt_` 쿼리·
   `AS OF` 원시 절 부재를 영구 검증(주석 언급은 허용).
5. **fake 흡수**: 기존 테스트 fake는 임베딩용 스텁
   (wire.HistoryStubs) 1줄로 마이그레이션 — 테스트 의미 보존.
6. **문서**: HISTORY v1.8.0·계약행 TestVersion0180Milestone·README
   EN/KO 배지·PLAN·release-gate green.

## 설계 결정

- 조사의 4메서드(LoopLog→LogEntries·ResolveAsOf·QueryAsOf·
  DiffRows)를 5메서드로 정제: ResolveAsOf는 무상태 조합이라
  wire.ParseAsOfSpec에 잔류(LogEntries 위합성), Diff 계열은
  시그니처 명료성으로 3분할(DiffRows·DiffStat·DiffCommits).
- AsOfQuery.Table은 식별자 화이트리스트(knowledge·
  active_knowledge)로 주입 면역. 해시 charset 재검증(asOfHashRe)
  은 구현측 이관.
- read의 "뷰+AS OF = 현재 정의+과거 행" 폴백(base 테이블 재시도
  안내) 구문은 db 구현 내부로 이동.

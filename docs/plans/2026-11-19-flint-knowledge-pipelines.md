## 0. 철학 — 핵심 가치 (2026-11-20 확정, 보강판)

**전제**
- **P1 오라클 없음** — flint는 세계의 상태를 알 수 없다. 관측된 증거만
  안다. 모든 자동 판정은 이 전제에서 출발(증거 누적 방식만 허용).
- **P2 기억의 주인은 사용자** — flint는 관리인. 로컬 단일 사용자
  (ADR-0013)·삭제권·비간섭 5원칙의 근거가 되는 상위 전제.

**K원칙**
- **K1 현상태 가설** — 현상태에 관한 지식은 근거·조건·신뢰도를 단
  믿음이다(pending/active/superseded는 서류가 아니라 인식 상태).
  역사 사실은 정착 기록(가설 아님) — 변동성 계층의 불변 계층과 일치.
- **K2 증거 가중치·선호/사실 분기** — 증거 종류별 가중치(사람 교정 >
  실사용 피드백 > 세션 증류 > 수입 > 에이전트 추론). 위계는 서열이
  아니라 가중치 — 면책 특권 없음(무검증 자동 승격 금지). 선호 교정은
  사용자가 구성적 원천(교정=개정 선언), 세계 사실 교정은 최강 증거
  (검증 경유).
- **K3 저장은 비용, 회상이 가치** — 회상 안 되는 지식은 부채(토큰·순위·
  주의 오염). 감쇠 저항은 빈도 + 최고 기여도(저빈도 고가치 보호).
  안 쓰임 ≠ 낡음 — 별개 회로.
- **K4 진실의 수정은 무효화(append-only)** — 과거의 틀림도 데이터.
  K4는 인식론적 수정(무효화·선행 관계 보존)만 지배 — 존재 제거(보안·
  프라이버시 expire)는 별개 레지스터. 현행 실현(UPDATE 금지·supersede·
  bi-temporal·dolt 감사)의 명문화.
- **K5 사실은 조건·출처·시점과 한 몸** — 맥락 없는 사실은 버그 발생기.
  조건 평가는 재점검 큐에서만(회상 시점 평가는 P1 위반).

귀결: K1·K2 → §4 교정·환류·모순 감지 / K3 → §5 병합·감쇠 개량 /
K5 → §5 조건 태그·provenance / §6 만남 순간 판정은 P1·K2의 실현
형태 / K4는 기준점(신규 개발 불필요).

## 4. 교정 플로우 — 입구·처분 (K2 분기 반영)

- **감지 경로 후보** (비간섭·프라이버시 전제, 택일 보류)
  - A안: 어댑터 훅 확장(사용자 프롬프트 계열 훅) — 교정 후보만 최소
    추출, 전체 발언 캡처 금지. 하네스별 가용 훅 차이 조사 필요.
  - B안: 에이전트 계약 유도 — 교정 인지 시 즉시 `flint write`(신규
    source) 적립. 구현 최소·어댑터 무관, 에이전트 순읬도가 품질 결정.
- **처분 분기(신설, 2026-11-20)** — K2 선호/사실 이원화의 구현
  - 선호 교정 → **즉시 개정**: 신규 적립 + 구 항목 supersede(사용자
    선언 자체가 원천 — P2·K2).
  - 세계 사실 교정 → **검증 경유**: pending 적립(최강 증거 가중) 후
    승격. 잘못된 교정 1건의 오염(gaslighting 벡터) 차단.
  - 교정 표적 식별은 §6 쓰기 echo의 근사 이웃으로 탐색.
- **구조 원칙(공통)** — 입구 다각화·종점 수렴: 모든 케이스는 공통
  종점(pending → approve)으로 모이고, 4연산·content_hash dedup·승격
  회로는 재사용. 케이스 정의는 코드 등록표 단일 소스(단일 소스 + 동질
  가드 준용). source 채널 확장도 등록표에서.

## 5. 낡은 지식 감지·변동성 계층 (2026-11-20 편입)

- **낡음 신호 5종** (증거 누적 — P1): ①모순 발화(신규 적립과 충돌)
  ②bad_recall(회상했는데 틀림 — G6 관측 자산) ③사용자 교정 표적
  ④TTL 경과(계층별 유효기간) ⑤근원 변화(옵시디언 원본·git·import
  원본 해시 — flint는 인덱스 계층이므로 원본-파생 불일치 = 낡음).
- **처분**: 자동 삭제 없음. `maintain --stale-audit` 승인제(decay-audit
  패턴) → supersede / expire / **재확신**(유효기간 리셋).
- **변동성 3계층** — 불변(역사·ADR 사실 — 감쇠 면제) / 조건부(선호·
  관례) / 휘발(버전·경로·도구 상태). 분류는 출처·주제 기본값 + 개별
  오버라이드(행마다 판단 안 함).
- **조건 태그** — "어떤 조건에서 유효" 명시(예: 엔진 미지원인 동안).
  조건 파열 시 재점검 큐 — 낡음 감지가 추측에서 점검 가능한 트리거로.
- **감쇠 개량(K3)** — 저항 = 빈도 + 최고 기여도. 불변 계층 면제로
  "잘 안 불리는 영구 참"의 아카이브 결함 해소.
- **후속 보완 후보** — 유사 병합 merge-audit(정확 hash만 잡는 dedup
  사각 — top-k 오염·토큰 낭비)·환류 일반화(bad_recall→지식 상태)·
  relations 이웃 회상(`read --related`)·회상 근거 표시(`--why`).
  모순 사전 감지·병합 후보 발굴은 §6 쓰기 echo로 실현.

## 6. 만남 순간 판정 — 쓰기 echo·회상 플래그 (2026-11-20)

원리: 판정의 진짜 비용은 연산이 아니라 **문맥 재구축**. 쓰기·회상
순간에는 판정에 필요한 문맥이 무료로 존재하므로 그 순간 흡수하고,
배치(census)는 잔여 부채만 청소한다 — "태어날 때 심사받고, 자면서
나머지를 정리". 우아함 준거: 신규 부품 0·판정 1회(같은 질문을 두 번
안 묻기)·수축하는 배치. 목표 측정치는 "KB 신뢰 유지 한계비용이
시간에 따라 감소".

- **쓰기 echo(핵심)** — write 파이프라인(검증 → hash dedup →)에
  근사 스캔 단계 삽입: `lib/query/suggest.go` bigramDice(NFKC rune
  bigram Dice)·자모 bigram 재사용 — read 회상 엔진과 동일 스코어.
  응답에 근사 이웃 상위 k(id·스코어)를 첨부하면 작성 에이전트가 그
  순간 NOOP/ADD/UPDATE+supersede를 판정(쓰기 3계층과 동일 — 판정
  우선순위 NOOP>삭제>갱신>추가는 Mem0 관례와 같은 방향, 계약
  명문화). 단일 메커니즘이 dedup·모순 사전 감지·병합 후보 발굴·
  교정 표적 식별 4표면을 지원. 조사 확인: related-on-write(쓰기
  응답 유사 항목 반환) 선행 사례 미발견 — flint 신규 기여.
- **지연 JOL 규칙** — 즉시 판정은 과신(지연 판단이 더 정확하다는
  메타기억 연구 확립 — §11). echo 산출은 후보 제안 한정, 확정은
  지연(승인·재점검 경유).
- **회상 건강 플래그** — read 응답 행별 age·저회상·stale 증거 점수
  부여 → 사용 중 환류(G6 bad_recall 회로 재사용).
- **census(에이전트 전수조사) — 잔여 청소로 축소** — 장기 미사용
  행 순회·레거시 import 정리. 5단계: 결정론 후보 수집 → 지시서(청크·
  체크포인트·판정 계약) → 에이전트 판정 → 게이트 검증(산출 JSONL·
  exit 3 자가수정) → 승인·감사(소스 마킹으로 라운드 일괄 무효화).
  통제 장치: 블라인드 데코이(정상 답 NOOP인 통제행 주입 — 라운드
  품질의 결정적 계량)·쿼럼/티어링(고위험 연산 영구 사람 승인)·판례
  (census 판정 자체를 지식행 적립 — 모델 간 안정 앵커)·NOOP 사전
  명시·인사이트 생성 기본 비활성.
- **스케일 아웃** — 현 규모(수천~수만 행) bigramDice 전스캔 Go
  밀리초급. 10만 행 접근 시 행별 MinHash 스케치 저장(후보
  ekzhu/minhash-lsh). SimHash(부분 겹침 약함)·Bloom(유사도 판정
  불가) 부적합. 지표는 PERF 문서로.
- **관계 어휘 확장 검토** — Oracle AI Agent Memory 26.8의 타입 관계
  5종(supersedes·refines·supports·contradicts·duplicates) 참고:
  모순 감지=contradicts·병합=duplicates 관계로 표현.

## 12. 관측 데이터 고도화 (2026-11-21 브레인스토밍·자체 피드백 반영)

방향 확정(사용자 선택 1·3·4): 튜닝 루프(T)·사용자 가시성(U) 전체,
기반 인프라 우선. 신규 회로 계측(W)은 선행하지 않고 이후 기능
마일스톤 착수 시 계측 설계를 동반(v1.17.0처럼 기능만 먼저 나가는
소급을 되풀이하지 않는다는 취지 — 이미 나간 echo는 W1로 소급).
동일일 자체 기획 피드백 반영: T1·T2 재설계(스코어 열 근간)·T3
스냅숏 방식·W1 대리책 명시·T4 축소·rollup 스키마 제약 명시.

### 공백 (2026-11-21 조사)

- write 계열 이벤트 부재 — echo 스캔 결과·판정 귀결 미계측(v1.17.0
  등록표가 "계측 소스 없음"으로 명시).
- rollup 부재 — daily 보존 14일을 넘는 장기 추세 불가(트렌드는 7v7
  한계).
- 분포·시뮬레이션·튜닝 변경 이력 전무 — TUNING §0 "14일 관찰 후
  조정" 루프의 효과 확인(후 검증) 도구 없음.
- 계측 실패는 silent(§13) — 실패해도 지표가 조용히 0을 말한다.
  "진짜 0인지 계측 사망인지" 구분 수단 없음(→ O 계열).

### 저장 3계층 규약 (공통 아키텍처 — 피드백 반영 개정)

| 계층 | 저장 | 보존 |
|---|---|---|
| 카운터 | `daily:*` 플랫 키(현행) | `daily_retention_days` |
| 원시 이벤트 | 이벤트 테이블 5종 + 열 확장(아래 T0) | `events_*_retention_days` |
| 장기 | 주간 rollup 행 — PruneDaily 삭제 시 집약 | 별도 한도 키 |

- rollup 행은 **분자·분모 카운터**를 적립한다(파생 비율 금지 —
  주간 비율의 평균은 수학적으로 틀리며 임의 윈도 재계산이 막힘).
- 당초 검토한 저장 히스토그램 daily 키는 폐지 — 지표×버킷×일
  카디널리티·read 경로 예산 침범 없이 T0 스코어 열로 같은 정보.
- 단일 소스는 report effect 객체 확장(진단·profile과 동일 패턴).
- 계측 실패 silent(§13)·read/write 경로 왕복 예산(≤5 쿼리) 준수.
- 신규 열·테이블은 스키마 버전 상향(additive) 병행.

### T — 튜닝 루프 폐쇄 (관측→조정→효과)

- **T0 스코어 열 저장(근간, 신규)** — read 스캔이 이미 계산하는 최고
  근사 스코어를 read_events에 1열(additive)로. 쿼리 본문은 저장 안
  함(§4 프라이버시)이라 재스캔 불가 — 이벤트 시점 저장이 유일 경로.
  추가 쿼리 0(기존 이벤트 삽입에 편승).
- **T1 분포 관측** — T0 열 파생(윈도 p50/p90 등). 장기 드리프트는
  rollup에 요약 통계만 적립. 임계값은 점 추정치(avg·p95)로 결정
  불가 — 분포가 근거.
- **T2 what-if 시뮬레이션** — 저장 스코어의 임계값 재분류("min_score
  0.15→0.10이면 zero_near N→M건") — 재스캔 없이 정확값.
- **T3 튜닝 변경 이력** — `flint tuning set` 기록만으로는 불완전
  (비등록 키는 psql 직접 수정 관례 — TUNING §2). **일일 meta
  스냅숏 + diff**(경로 무관)로 변경 이력·드리프트를 함께. 전후 비교는
  n=1 상관 힌트 라벨(효과 주장 아님).
- **T4 정합 카드(축소)** — 기본값·현재값·드리프트 나란히(스냅숏
  파생). 당초 후보 '마지막 경고 시점'은 진단 발화 이력 미지원으로
  폐기(진단 이력 신설은 비용 대비 효과 의심).

### U — 사용자 가시성

- **U1 주간 rollup** — PruneDaily 시 집약 → 월간 추세·전월 비교·
  버전 업데이트 전후 비교(T0·T3와 함께 공통 기반).
- **U2 추세 확장** — 7v7(hit·fallback·top1 한정) → rollup 기반
  주요 지표 전반 + 방향성(호전/악화) 문장(당초 U4 흡수).
- **U3 대시보드 밴드** — HTML 뷰에 diag 임계값 참조선·정상 밴드.
- **U6 분절 뷰(후보)** — 이미 저장된 source(hook·cli·mcp)·태그의
  지표 분절(GROUP BY — 신규 계측 불필요). 채널별 회상 품질·태그별
  dead_pct(distillation 우선순위 근거). 출력은 로컬 보고서 한정.

### W — 신규 회로 계측 (기능 마일스톤 동반 원칙)

- **W1 echo 소급** — 근사이웃 발견율·관계별(dup/contradicts) 스코어
  분포. **판정 귀결은 직접 관측 불가**(flint는 에이전트 판정을 모름
  — P1) — 대리책: echo 반환 id → N일 내 supersede 표적 = 갱신 근사
  (Tier 2 상관). G8(쓰기 판정 효율) 후보.
- **W2 교정** — 승인 카운터(correction_approved)는 v1.17.0 T4 확보.
  잔여: 선호/사실 분기율·교정→supersede 지연·표적 재적립률(가스라이팅
  검출) — G7(지식 위생) 후보.
- **W3 낡음·변동성** — stale_score 분포·3계층별 분포·재확신 비율.
- **W4 환류** — bad_recall→무효화·교정 전환율(G6 확장).
  gap_approved·survived_sessions 카운터는 확보.
- **W5 census** — 데코이 정답률(§6 계량)·라운드 NOOP 비율·무효화율.
- **W6 증거 가중치 검증(신규)** — 소스별(correction·session·
  import·manual) 장기 생존율·회상률 비교. K2 위계(사람 교정 >
  에이전트 추론)를 가정으로 두지 않고 실측으로 검증하는 회로.

### O — 관측 건전성 (관측의 관측, 신규)

- **O1 신선도** — 이벤트 테이블별 마지막 ts 기준 끊김 표시(미사용과
  계측 사망의 구분은 불가 — 신호로만, P1). doctor 규칙 후보.
- **O2 커버리지** — 등록된 관측 키의 장기 미발화 → wiring 누락 의심
  표시(등록표 대조).
- **진단 규칙 확장 후보** — 신규 데이터 기반 3종: 튜닝 변경 직후
  지표 급변(T3×진단)·분포가 임계값에 접촉(T0×진단)·계측 신선도
  경고(O1×진단). 구현 시 METRICS §4.8 8규칙에 추가.

### 제안 회로 (proposal loop) — 튜닝도 지식처럼 (2026-11-21 점검·브레인스토밍)

튜닝 워크플로우 점검(2026-11-21) 결론 — 경고→조정 실전 단절·후검증
불가·모드 스위치만 채택 — 의 개선 설계. 지식 생명주기(pending→
approve·verdict→--apply)와 같은 모양으로 루프를 닫는다:
**증거→제안→승인→기록→검증**.

1. **발화·감지** — doctor 경고(기존) + 등록표 대조: fired_doctor_*
   누적 ≥ N → 재조정 규칙 발동. 등록표는 TUNING §0 트리거 표의
   코드화(규칙ID·감지원·키·방향·근거 문장 — pipeline case registry
   패턴, 단일 소스).
2. **제안 출력** — "제안: flint tuning set <key> <val> (근거: 경고
   N회 반복)". T0·T2 갖춘 키는 예상 효과 부착, 아니면 규칙 문장만.
   경고 계열 안내(§13) — 실행은 사람(복붙), 자동 값 변경 없음(P2).
3. **기록** — diff-on-write 스냅숏(T3): 매일 전체 키 로드(이미 매
   커맨드 수행 중 — 추가 쿼리 0)와 직전 스냅숏 비교, 다르면 append.
   저장량 = 변경 횟수, psql 경로도 포착.
4. **후검증** — 스냅숏 변경 시점 × rollup(U1) 전후 주간 비교 + 진단
   확장 "변경 후 급변"(위 3종). n=1 상관 힌트 라벨 — 효과 주장 아님.

**정합**: P1(제안은 증거에서만)·P2·§13(자동 변경 금지)·우아함 준거
(§6 — 신규 부품 최소: 등록표·스냅숏·스코어열 3).

**기각 대안**: 완전 자동 튜닝(§13·P2 위반·오염 벡터)·가시성 강화만
(점검 반증 — 경고 노출돼도 조정 0)·무근거 프리셋 패키지(P1 위반 —
제안 회로가 증거 기반 프리셋을 자동 생성)·pending 지식행 재사용
(원천 계층 혼동).

**한계(명시)**: fired_*는 누적이라 "최근 반복" 구분 불가(daily 발화
키 후보 — 미결정). 제안 회로 단독으로는 조정 촉진만 — 후검증은
T3+U1 세트 필요.

### 스캔 성능 관측 (신규 — PERF 연계)

echo·suggest 근사 스캔의 p95 지연 계측 — 스케일아웃 전환 판단(10만
행 MinHash — §6)의 데이터 근거. PERF.md 측정 관례 준용.

### 유용점 (구현 시 획득)

| 변경 | 유용점 |
|---|---|
| T0·T1·T2 | 임계값 변경 전 정확 시뮬레이션 + 분포로 경고 원인 구분(버킷 경계 문제 vs 어휘·지식 격차) — 튜닝 시행착오 왕복 제거 |
| T3 | 튜닝 효과 후검증 — §0 14일 관찰 루프 폐쇄, 의도치 않은 값 변이 노출 |
| U1 | 전월비·월간 추세·버전 간 비교 — 14일 기억 한계 해소 |
| U6 | 채널·태그별 진단 — "어느 표면·주제가 병들었나" 직접 회답 |
| W1 | echo 존재 이유의 첫 계량, contradicts 밴드 실용성 검증 |
| W6 | K2 가정의 실측 검증 — 철학이 데이터로 회신 |
| O1·O2 | 지표가 조용히 거짓말하는 상황 탐지 |

조합 시그널: 스코어 열×rollup = 병합(잔여 이월) 착수 시점 근거·
스냅숏×rollup = 튜닝 변경 전후 주간 대조·echo×교정 = §4 B안(에이전트
계약 유도) 정확도 평가.

METRICS §4.6 후보와 겹치는 항목은 METRICS 정의를 단일 소스로,
본 절은 편성만. T/U 구현 시 METRICS 정의 병기는 doclint 게이트
후보(문서-구현 동기 의무).

## 목표

새 기기에서 `flint setup` 한 번으로 설치가 끝나고, 설치 중 실패는 원인별
처방으로 연결되며, 포트 충돌과 엔진 버전 편차를 코드가 해소한다. 스키마
변경 없음. 엔진은 Doltgres 유지.

## 0. 문제 (2026-11-23 조사 — 실측 수치 비인용)

1. **소스 체크아웃 전제**: `docker compose`를 현재 디렉터리 기준으로
   실행하고(`--file`·`--project-name` 없음) compose 파일을 내장하지 않는다.
   완료 안내도 `make seed`·플러그인 디렉터리(소스 경로)이다. 릴리스
   바이너리 사용자는 git clone이 사실상 필수.
2. **실패 문구 수렴**: compose 실패 전부 "start docker and re-run" 한
   문구 — 데몬 미기동·compose 파일 부재·compose v1·권한·내려받기 실패·
   포트 바인드 실패를 구분하지 않는다. 내려받기 중 출력이 없다(출력을
   실행 종료까지 묶음).
3. **첫 실행 재실행 필수**: DB 기동 전에 시작하면 저장소가 없어 ping이
   degraded(exit 1)가 되고, 두 번째 실행에서야 마이그레이션이 된다.
4. **엔진 버전 미고정**: compose는 `:latest`, CI만 다이제스트 고정.
   바이너리↔엔진 호환 조합이 정의되지 않았다.
5. **포트 5434 고정**: 선점 시 경고 1줄 후 그대로 진행(바인드 실패 또는
   다른 서버 연결). 변경은 추적 파일 편집 + FLINT_DSN 수동 설정. 포트가
   상수로 흩어져 있다(`DefaultDSN`·`doctorPort`·테스트 기본값 3종).
   config.json의 기록자가 없어 기존 설치는 전부 "명시 설정 없음"이다.
   doctor port 검사는 `docker compose ps`라 저장소 밖에서는 skip.

## 1. 레퍼런스 조사 (2026-11-23)

- **엔진 배포 형태**: 공식 Docker 이미지와 네이티브 바이너리(GitHub
  Releases — darwin/linux arm64·amd64)·homebrew-core 수식. 서버 전용.
  https://www.doltgres.com/docs/introduction
- **Compose 관례**: 최상위 `name:`·`--project-name`으로 디렉터리 무관
  프로젝트명 고정, `${VAR}` 치환, `--wait-timeout`은 기동 대기 전용
  (내려받기 시간 미포함). 컨테이너 식별은 라벨
  `com.docker.compose.project`의 정확 일치.
- **내부 자산**: `go:embed` 선례(lib/sqlfs·cosign.pub) · v1.25.0의
  ComposePsFn seam·엔진 버전업 절차(RUNBOOK §11) · v1.27.0의
  `flint seed --demo`(setup ③ 안내 교체)·checkVersions · update.go의 원자
  교체 관례.

## 2. 설계 — 마일스톤 4건 (기재 순서 = 착수 순서)

### M1 설치 기반 — compose 내장·엔진 핀·오류 분류·첫 실행 1회 성공

- 신규 패키지 `lib/engine`(엔진 배치 단일 소스):
  - compose 파일 `go:embed`(개발용 루트 `docker-compose.yml`와 바이트
    동치 가드) · 최상위 `name: flint`로 프로젝트명 고정 · 실행은 항상
    `--file <FLINT_HOME 에 전개한 파일> --env-file <FLINT_HOME>/engine.env`.
    setup·teardown·doctor(ComposePsFn)가 같은 경로를 쓴다.
  - **엔진 핀**: `EngineImage`(다이제스트) 상수 — compose 기본값·CI 서비스
    이미지·상수의 3방 동치 가드(문자열 매칭 — go.mod에 yaml 라이브러리
    없음). **핀은 현행 CI 다이제스트로 두어 엔진 버전업과 분리한다.**
  - **변수 주입**: `FLINT_ENGINE_PORT`(M2)·`FLINT_ENGINE_IMAGE`(사설 미러).
    이 환경 파일에는 비밀값을 두지 않는다(기본 자격증명은 compose 상수) —
    자격증명 운반처는 v1.31.0의 엔진 설정 파일 1곳.
- **setup 재실행은 엔진을 교체하지 않는다**: 실행 중 이미지가 핀과 다르면
  경고 + RUNBOOK §11 절차 안내만 한다(바라는 상태 파일만 갱신). 엔진
  버전업은 사람 운영자 절차이며, 핀 갱신은 flint 릴리스를 통해 일어난다 —
  RUNBOOK §11 3단계를 그에 맞춰 재작성한다.
- **내려받기 분리**: 이미지가 로컬에 없을 때만 `compose pull`을 먼저
  실행하고 TTY에서 진행률을 스트림 → 이후 `up -d --wait`. 기동 대기 예산은
  thresholds `engine_wait_seconds`(첫 실행에는 meta에 접근할 수 없어 코드
  기본값만 유효).
- **오류 분류기**(순수 함수·표 기반): 데몬 미기동 / compose v1 전용 /
  권한 거부 / 내려받기(한도·TLS·호스트) / 포트 바인드 / 건강 검사 시간
  초과 → 각각 처방 1행(OS별 기동 명령 포함). 미분류는 원문 유지.
  compose v1 전용 환경은 `docker-compose` 1회 폴백. 런타임은 Docker CLI를
  그대로 노출하는 경량 런타임(Colima·OrbStack·Podman)도 자동 인식.
- **첫 실행 1회 성공**: 엔진 기동 뒤 저장소를 재생성(Ping 재시도)해
  ping·migrate를 같은 실행에서 완결. `st == nil` 경로 폐지.
- **안내 문구**: `SetupSteps()`·`setupNext` 갱신 — 시드 안내는 v1.27.0의
  `flint seed --demo` 승계, 하니스 안내는 마켓플레이스·`setup --mcp`로.
- **기존 설치 보호**: 기존 컨테이너는 compose 라벨
  (`com.docker.compose.project`)의 정확 일치로 식별한다(이름 접두 일치는
  `flint-test`를 오탐). 프로젝트명이 `flint`이 아닌 기존 엔진·볼륨이
  있으면 경고하고 **정지**한다(사용자 결정 — 자동 이전·자동 재생성 없음).
  `make up/down`은 cwd 기준이라 워크트리 간 핀 차이가 있으면 타 컨테이너를
  재생성할 수 있어, flint 경로에 위임한다.
- **엔진 메모리 상한 기본값**: v1.29.0 측정 스파이크가 채택하면 compose
  환경에 Go 런타임 상한 기본값을 넣는다(코드 기본값 + thresholds).
- 문서: QUICKSTART 재작성(바이너리 우선)·README EN/KO 설치절·
  contracts/cli.md·RUNBOOK §11·`scripts/install.sh` 점검·ADR-0020(엔진
  핀·프로젝트명 고정)·ADR-0013 갱신(포트 가변·엔진 모드).

### M2 포트·연결 — 자동 배정·선점자 식별·엔진 확인

- **접속 대상 결정 규칙**(단일 순서): `FLINT_DSN` 환경(단, 기본값과
  동일하면 관리형 절차로 취급) > config.json `dsn` > 기존 설치 판정 >
  신규 설치 절차.
- **기존 설치 판정**: 해소된 DSN으로 ping이 성공하거나, 기본 포트 선점자가
  라벨 `project=flint` 컨테이너면 기존 엔진을 채택하고 그 포트를
  config.json(0600)에 기록한다. 선점자가 다른 프로젝트의 flint 엔진이거나
  비flint 프로세스면 경고 후 정지한다(자동 배정·재생성 금지).
- `flint setup --port N`·자동 배정: 신규 설치에서 기본 포트가 막혀 있으면
  루프백 바인드 시험으로 빈 포트를 찾아 config.json에 기록하고 compose에는
  변수로 주입한다. 추적 파일은 편집하지 않는다.
- **선점자 식별**: `lsof`(부재 시 생략) + `docker ps --filter publish=<port>`
  로 프로세스·컨테이너명 안내.
- **엔진 확인 악수**: 접속 직후 엔진 종류·버전 확인 — Doltgres가 아니거나
  핀과 다르면 원인형 오류(exit 1) + 처방. 관리형 엔진은 핀 일치, 외부
  엔진은 버전 차이 경고. **경질 실패는 사람 명령(setup·doctor)에 한정** —
  훅·MCP 경로는 조용한 skip 계약(exit 2)을 유지하고 doctor `engine`
  fail로 가시화한다(`flint update` 뒤 핀 불일치 상태가 훅을 막지 않게).
- doctor `port` 재작성: `docker compose ps` → 소켓 탐사 + `docker ps`
  필터(저장소 무관). 포트는 상수 대신 해소된 DSN에서 유도하고 컨테이너
  식별은 라벨 정확 일치. checkVersions(v1.27.0)에 엔진 버전 연결.

### M3 외부 엔진 모드 (루프백 한정)

- `flint setup --engine-url`: 엔진 설치·기동 없이 접속 대상을 기록(M2
  규칙) → 엔진 확인 악수 → migrate. "이 머신엔 아무것도 설치하지 않음"
  경로 — 사용자가 원하는 방식으로 분리 운영한 **전용 Doltgres**에만 붙인다
  (바닐라 PG·범용 DB는 엔진 확인 악수가 거부).
- **범위는 루프백 한정**(사용자 결정): 원격 엔진은 네트워크 구간·자격증명
  이동이라 ADR-0013(위협 모델) 개정과 함께 재판정한다. 비루프백 DSN은
  거부한다.
- **비밀값 유출 방지**: DSN은 `FLINT_ENGINE_URL` 환경변수 >
  `--engine-url-file <PATH>` > TTY 숨김 입력으로 받는다. 인라인 인자값은
  거부한다(셸 이력·프로세스 목록 비노출). 출력은 render 살균 조크포인트의
  DSN 마스킹(sync 선례).
- config.json에 `engine.mode`(managed-container | external)를 기록하고,
  v1.29.0의 `purge-dropped`를 **관리형 모드 한정**으로 강화한다.

### M4 네이티브 엔진 L0 스파이크 (v1.31.0 착수 조건)

- 핀 버전 바이너리 내려받기·해시 검증 → `doltgres -data-dir` 기동 →
  실DB 테스트 스위트 실행(전용 DSN) → 디스크·메모리(유휴·부하 후)·기동
  시간 실측 → 서비스 등록(launchd·systemd user) 실증 → 컨테이너↔네이티브
  전환 1회 실증.
- **통과 기준**: ① 실DB 테스트 전부 통과 ② macOS·Linux(GitHub ubuntu
  러너의 `systemctl --user`) 각 1환경에서 기동·자동시작 등록 성공 ③ 전환
  실증 — 컨테이너 합성 데이터를 복사한 뒤 dolt_log 깊이·AS OF 결과가
  동일 ④ 구핀→신픈 기동·구 디렉터리 롤백 ⑤ 정지(SIGTERM)→재기동·KeepAlive
  재기동 후 무결성 ⑥ 초기 자격증명·로그 행태 확인 ⑦ 자원 실측(메모리·
  디스크·기동 시간)이 컨테이너 대비 열등하지 않음. 측정은 통과를 걸러낸다.
- 산출: 결론 노트 1건(합성 벤치 수치 — PERF 관례). 통과 시 v1.31.0 착수,
  미통과 시 v1.31.0 closed. 미통과 시 Docker 없는 경로는 경량 런타임
  자동 인식(M1)이 대체안이다.

## 3. Ruling (사용자 결정 2026-11-23 포함)

- **기존 설치 보호 — 경고 후 정지**(사용자 결정): 프로젝트명이 다른 기존
  엔진·볼륨은 자동 이전하지 않는다.
- **외부 엔진 모드 — 루프백 한정**(사용자 결정).
- **엔진 핀 — 다이제스트 단일·현행 CI 다이제스트**(CI 동치가 다이제스트라
  선택지가 없음. 버전업은 flint 릴리스로).
- **`make up/down`의 flint 경로 위임** — cwd 기준 compose 직접 실행 제거.
- **위저드에 엔진 모드 선택 단계를 추가하지 않는다**(플래그 경로만).
- **엔진 버전·보존 영역 조회 수단** — 빌드 시 실증.

## 목표

자율 튜닝의 정책·기록·가시성 기반 — **적용 0건·shadow 예측만**. 사람은
정책 설계자(§12.1)·관측 축적 조건 확정으로 v1.24.0 게이트 명문화.

## Ruling (G2)

- **스키마 v18 additive** — 스코프 표 v1.23.0 스키마란 "—"→"v18 additive"
  갱신(원칙 ④ 위반 아님·명시만).
- **B1 이중 구조** — 화이트리스트·안전범위·주 한도·규칙 = 코드 등록표
  (threshold_meta "등록 1곳+가드테스트" 패턴·auto 필드 확장). 모드 =
  meta `auto_mode`(off|shadow·**기본 off** — exposure_profile enum 선례).
  `tuning auto off|shadow` 서브커맨드. **초기 화이트리스트 =
  {suggest_min_score} 1키 auto:shadow** — A1 저장 스코어가 있어 §12.2
  "정확한 인과"층 유일 분류키(echo/conflict 스코어 미저장·진단 키는
  마스킹 벡터·행동 키는 §12.8 구멍 — 전부 manual).
- **B2 = tuning_predictions 테이블**(v18) — append-only(ts·trigger·key·
  cur·new·pred_zero_near_pct·pred_reclass_n·sample_n·rationale). 발화 =
  RecordReadEvent 꼬리 24h 게이트(rollup/snapshot과 동일 패턴·훅 순서
  갱신)·실패 silent·라운드 왕복 ≤5.
- **적중 = 회차 안정성** — 1적중 = 라운드 재분류 방향·최소표본
  (≥ zero_near_min_read)이 다음 라운드 재실행에서 유지. **K=3 연속·감지 임계 N=5회·관찰창 D=14일**(D는 TUNING §0 상속·
  K·N은 이번 확정). **"적중=안정성,
  인과 아님" 각주 필수**(§12.2 Tier 표기 승계).
- **B3 = 코드 등록표** — {Signal·판정 쿼리·Key·Direction·SafeRange·
  WeeklyMax·Auto·SuccessPair·ObsWindowD}. 초기 1행: **auto_zero_near_high**(진단 시그널과 접두 구분) →
  suggest_min_score 하향·성공쌍 (zero_near_pct 감소, hit_pct·read 수
  불변) — 마스킹 방어 구체화. **Diagnose 재사용 금지**(입력이
  ReportOutput 전체 — 등록표 판정 쿼리로 독립 정의·판정 키 임계는
  thresholds 단일 원천).
- **관측 축적 조건(v1.24.0 게이트)** — "shadow 라운드 ≥14회(2주) AND
  트리거 발화 ≥5회 AND 연속 적중 3 달성 — 미달 시 v1.25.0과 순서 교환
  (원칙 ③·교환 시 배분 표·상태 표 비고·의존 메모 동일 커밋 갱신)".
- **B6 = threshold_snapshots 3열**(v18: origin·trigger·rationale —
  snapshot.go "deferred to v1.23.0" 이행). v1.23.0은 적용 0건이라
  origin=auto 행 없음 — 스키마·스탬프 경로만.
- **C1/C2/C6 = tuning 하위** — `flint tuning what-if <key> <value>`
  (zero→near 전환수·신 near_pct·p50/p90 — 1~2쿼리·nearest-rank 선례)·
  `flint tuning status`(기존 list 뼈대+drift+fired 카운터). report는
  미확장(에이전트 표면 단일 JSON 원칙 — what-if는 사람 정책 분석).

## 계약

### 스키마 v18 (additive)

1. `tuning_predictions(id bigserial PK, ts timestamptz NOT NULL DEFAULT
   now(), trigger text NOT NULL, key text NOT NULL, cur text NOT NULL,
   new text NOT NULL, pred_zero_near_pct double precision NOT NULL,
   pred_reclass_n int NOT NULL, sample_n int NOT NULL, rationale text
   NOT NULL)` + 인덱스 (ts).
2. threshold_snapshots `origin text NULL`·`trigger text NULL`·
   `rationale text NULL` 3열.
3. 스테이징: tuning_predictions audit 계열·레지스트리·v17→v18 게이트·
   schema.sql 종착상태.
4. meta `auto_mode`(TuningMetaKeys 확장·enum 검증)·fired 카운터는
   `fired_auto_<signal>` 접두(metaKnownPrefixes fired_ 승계). **자기 키
   등록: metaKnownKeys에 auto_mode·last_shadow_at 추가·metaKnownPrefixes에
   auto_streak_ 추가(자기참조 오탐 방지 — R80-1 클래스 방어).**

### B1 정책

- 등록표 auto 필드(threshold_meta 확장 또는 별도 코드 상수 — 구현
  선택)·`tuning auto off|shadow`(SetMetaKV 멱등·usage 갱신)·auto
  아님 키 what-if/auto 지정 시 exit 3.

### B2 shadow 회로

- read 꼬리 순서: rollup→prune→snapshot→**shadow**(가드테스트 갱신).
  24h 게이트 meta `last_shadow_at`(1h in-process 캐시 — 기존 훅 관례)·실패 silent.
  라운드: 게이트 1+트리거 판정 1+what-if 재분류 1+INSERT 1.
- 트리거 판정: 등록표 쿼리(auto_zero_near_high — 14일 창 zero행
  near_score 분포·최소표본). 발화 시 fired 카운터 bump·예측 행
  INSERT·전회 예측과 비교해 연속 적중 카운터 갱신(meta
  `auto_streak_<key>`). **streak 규칙: (a) 첫 발화 라운드 = 1로 시작
  (b) 제안값 변화(0.15→0.12)도 방향 유지면 적중 (c) 트리거 미발화
  라운드는 streak 유지(리셋 아님) — 리셋은 방향 반전·최소표본 미달
  시만. off 전환 시 streak·fired·게이트 스탬프는 유지(파기 아님 —
  재전환 시 이어짐·문서 명시).**
- **라운드 쿼리 산정: 게이트 1+트리거 1+재분류 1+INSERT 1+메타 갱신
  1회 배치(streak UPSERT·fired bump·last_shadow_at 단일 문) — 총 5왕복 상한 준수·쿼리 카운트 주석
  (rollup 선례)으로 실측 고정.**
- 24h 게이트는 meta 확인만(기존 3훅과 동일) — **1h in-process 캐시(기존 훅
  관례)**.
- 제안값: 안전범위 내·방향은 등록표(주 한도는 v1.24.0 집행).

### C1/C2/C6

- `tuning status` — list 확장(drift=현재−기본·fired 카운터·auto 등급·
  streak·관측 축적 조건 진행률).

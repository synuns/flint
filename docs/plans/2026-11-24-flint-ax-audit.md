# flint AX 전체 점검 + 멀티 하니스 — 영역 D (2026-11-24)

상태: draft
원천: 2026-11-24 브레인스토밍 세션(사용자 제안 — "에이전트가 모든
기능에 접근하기 쉽도록")·마스터 인덱스
준수: 비간섭 5원칙·exit 4종 계약·CLAUDE.md

## 1. 목표·위상

flint는 사람이 쓰는 목적이 아니므로 "모든 기능이 에이전트에게 쉽게
접근 가능한가"를 전수 점검하고, 필요하면 AX 관점으로 재설계한다.
산출은 영역 B의 교정 입구(A안/B안) 결정 입력이 된다.

## 2. 점검 축 (감사 루프 — 각도 로테이션 관례 승계)

1. **표면별 접근성** — CLI 29종·MCP 도구 5종·플러그인 훅·스킬·
   커맨드 각각에 대해: 에이전트가 첫 시도에 성공하는가(인자·플래그·
   출력 파싱 가능성).
2. **오류 계약** — exit 4종·error 키·메시지의 자가수정 유도성
   (exit 3이 실제로 재시도에 충분한 정보를 주는가).
3. **usage·문서 표면** — usage 노출·SKILL.md·contracts의 에이전트
   관점 정확성(사람 전용 명령의 명시적 구분이 유지되는가).
4. **주입·데이터 경계** — [flint] 접두 경계·살균이 에이전트 흐름을
   막지 않는가(비간섭과 접근성의 긴장 점검).
5. **실패 모드** — 엔진 다운(exit 2 조용한 skip)·타임아웃·훅 실패가
   에이전트 작업을 지연시키지 않는가.

## 3. 멀티 하니스

- 접점 3개(CLI·MCP·Claude Code 플러그인) 중 하니스 전용 계층 식별.
- **어댑터 확장은 트리거 대기 유지** — 본 영역은 호환 매트릭스
  문서화만 선수행(어떤 하니스에서 어떤 접점이 동작하는지·훅 차이).
- 하니스별 훅 가용성 조사 결과는 knowledge-pipelines §4 A안의
  "하네스별 가용 훅 차이 조사"를 흡수한다.

## 4. 방법

- 감사 루프(각도 로테이션·패치 회차 관례) — 무인 운용 승계.
- 발견은 등록표(유형·표면·수정처)로 축적 → 수정 배치.
- 합성 시나리오 기반 검증(개인 운영 DB 미사용).
- **결정론 경계(2026-11-24 자체 리뷰 보강)** — T2는 제품 회로의 제약.
  감사·리뷰의 실행 도구로 에이전트(LLM) 사용은 무인 리뷰 루프 전례대로
  허용 — 제품 코드의 LLM 유입만 금지한다.

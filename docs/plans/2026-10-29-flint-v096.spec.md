## 1. 배경 — 실측·사용자 지시

- zero_pct 12%(read 16회 중)·read_calls 16 — §15 트리거(제로히트 20% 초과 +
  read_calls≥50)는 미발동이나 **사용자가 직접 검색 고도화 단독 버전을
  지시**(2026-10-29) — 트리거 조건을 사용자 재량으로 대체 발동.
- 현행 매칭은 `lower(topic || ' ' || summary) LIKE lower('%q%')` 단일 구문
  부분일치(lib/query/read.go:66) — 질의가 표현 어순·표기와 다르면 미스.
- 제로히트 사례 유형: 복수 단어 질의("백업 복구 절차" ↔ 저장 "flint 백업
  복구는 …")처럼 토큰은 전부 존재하지만 연속 부분문자열이 아닌 경우.

## 3. 요구사항

### R1 토큰 폴백 재랭킹
- `flint read <q>`에서 구문 매칭이 제로히트일 때만: q를 토큰으로 분해
  (공백 분리·선행/후행 구두점 제거·빈 토큰 제거)해 각 토큰
  `lower(topic||' '||summary) LIKE %tok%`의 **OR** 로 재검색.
- 폴백 결과 정렬: 토큰 정합수 내림 → 기존 RankOrder(topic 정합 >
  confidence > 최신 > last_read). 앱 사이드(Go) 정렬.
- **구문 매칭 히트 시 현행 경로 완전 불변**(SQL·랭킹·출력·exit·계측).
- 폴백도 제로히트면 기존 제로히트 출력 그대로. 필터 플래그(--tag 등)는
  폴백에도 동일 적용. active_knowledge 뷰 강제·토큰 예산(한 줄 JSON·
  limit 상한) 계약 불변.

### R2 폴백 계측 노출
- 폴백 발생을 meta 키 `read_fallback_calls`(int 누적)로 증분 — 기존
  계측 패턴(조용히, 조회 불해) 승계.
- `flint status`에 `read_fallback_calls` 필드 추가(기존 필드·순서 불변,
  미설정 시 null — v0.6 status 확장 선례 승계).

### R3 문서 동기화
- README.md·README.ko.md: read 설명에 토큰 폴백 1줄(구문 미스 시 단어
  재검색).
- docs/PLAN.md: v0.9.5·v0.9.6 마일스톤 기록 추가(v0.9.5분 미기록 상태).

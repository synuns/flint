## 목표

운영 엔진에서 테스트를 물리적으로 분리해 잔재·부하 누적을 차단하고,
운영 엔진에 쌓인 삭제 잔재를 사람 운영자가 안전하게 되회수할 수 있게
한다. 사용자 표면 변화는 사람 운영자 명령 1종과 doctor 경고뿐이다.
스키마 변경 없음. **v1.27.0보다 먼저 착수한다**(누적이 진행 중 — 사용자
결정).

## 0. 문제 (2026-11-23 조사 — 실측 수치 비인용)

1. **테스트 격리가 DB 수준**: 테스트 기본 DSN이 운영 엔진 그대로이다
   (같은 엔진의 flint_test). CI도 job 환경에 `FLINT_TEST_DSN`이 없고
   Makefile 기본값에 의존한다. Doltgres는 DROP한 DB를 보존 영역으로 옮기므로
   임시 DB 잔재가 운영 엔진 볼륨에 누적되고, DROP 실패 DB도 잔존한다.
   엔진 메모리도 테스트 부하를 그대로 받는다. 실DB 헬퍼는 9패키지 26파일에
   중복이고, 운영 DSN을 직접 읽는 테스트가 그 밖에도 남아 있다(구 포트
   기본값 잔존 포함).
2. **되회수·경고 수단 부재**: 삭제 보존 영역을 비우는 명령의 래핑이 없고,
   doctor 크기 경고(v1.25.0)는 보존 영역을 보지 못한다.
3. **엔진 메모리 미측정**: 테스트 부하 뒤 메모리가 높게 유지되는 원인과
   런타임 상한의 효과가 측정되지 않았다.

## 1. 레퍼런스 조사 (2026-11-23)

- **삭제 보존 영역**: Doltgres는 DROP된 DB를 임시 보존 영역으로 옮기고
  `dolt_undrop()`으로 복원할 수 있다. `dolt_purge_dropped_databases()`가
  영구 삭제(되돌림 불가·SUPERUSER).
  https://www.doltgres.com/docs/reference/version-control/dolt-sql-functions
- **내부 자산**: 프로세스 간 flock 선례(`flint-drill.lock`)·advisory lock
  선례(slow 스위트 직렬화) · v1.25.0의 maintain --yes 가드·doctor 등록표·
  thresholds 6곳 등록·ComposePsFn·EngineStatsFn seam.

## 2. 설계 — 마일스톤 2건

### M0 테스트 전용 엔진 분리 (물리 격리) — ADR-0019

- `docker-compose.test.yml` 신설 — 프로젝트명 `flint-test`, 이미지는 CI와
  같은 다이제스트(동치 가드 테스트), `127.0.0.1:5499:5432`, `restart: no`.
  전용 볼륨(휘발 취급 — `make test-down`으로 `-v` 회수).
- **CI 정합(선행)**: ci.yml job 환경에 `FLINT_TEST_DSN`(서비스 컨테이너의
  5434)을 명시해 Makefile 기본값 의존을 끊는다. CI 환경에서 접속 실패는
  skip가 아니라 fail. 실DB skip 0건을 단언하는 센티널 단계를 둔다.
- 신규 패키지 `internal/testengine`(테스트 전용 — 프로덕션 패키지가
  import하면 소스 가드로 차단):
  - **DSN 해소**: `FLINT_TEST_DSN` 설정 시 그대로. 미설정 시 전용 엔진
    기본값. 운영 DSN 폴백 금지 — `testDSNFromEnv`의 FLINT_DSN 폴백 제거.
  - **엔진 보장**(lazy): 실DB 테스트가 처음 접속할 때만 — 미기동이면
    `docker compose -f docker-compose.test.yml up -d --wait`을 1회 시도
    (패키지 병렬 기동은 프로세스 간 flock으로 직렬화 — 기존 선례의 별도
    lock 파일). 실패 시 로컬은 skip + 경고 1행, CI는 fail. eager TestMain
    (slow 스위트 lock)은 접속 필요 시점까지 지연시켜 단위 테스트만 실행할
    때는 엔진을 띄우지 않는다.
  - **스크래치 수명주기**: 생성 등록 → 정리 시 연결 종료 후 DROP 재시도
    (백오프) → 실패 이름은 런 종료에 1행 보고.
  - **런 종료 정리**: 이 런이 만든 스크래치를 일괄 DROP하고, 해소 출처가
    전용 엔진 기본값일 때만 `dolt_purge_dropped_databases()`를 1회 실행.
- **수렴 범위**: 9패키지 26파일의 개별 헬퍼 + 운영 DSN을 직접 읽는 테스트
  4곳(seed·asof·readhot·mcp tools — 구 포트 기본값 잔존 포함). DROP 37곳
  단일화·기본 DSN 상수 3종 단일화·소스 가드 "`*_test.go`의 FLINT_DSN 직접
  읽기 0건".
- 계약 갱신: 기본 테스트 DSN을 고정하는 테스트 3종을 "기본 테스트 DSN은
  전용 엔진(운영 포트 아님)" 회귀로 교체 · ADR-0010의 "tests 기본 DSN 5434"
  준항목 슈퍼세드 · Makefile 기본값·`test-up`/`test-down` · RUNBOOK
  "테스트 DB 장기 운영 위생"·"실DB 테스트 격리·러너" 재작성(격리 후에도
  전용 엔진 하나의 경합 규율은 유지).

### M1 엔진 점유 — purge 명령·doctor 경고·메모리 측정

- `flint maintain --purge-dropped [--yes]`: 기본 dry-run(복원 가능 목록·
  개수) → `--yes` 시 `dolt_purge_dropped_databases()`. 보존 영역은 엔진
  전체에 적용되므로 **해소된 DSN의 호스트가 루프백일 때만 허용**한다
  (v1.30.0이 엔진 모드 모델을 도입하면 관리형 모드 한정으로 강화).
  dry-run 목록 조회가 지원되지 않으면 `--yes`를 금지한다. 사람 운영자
  명령(RUNBOOK만 기재 — sync·--gc 선례).
- doctor 경고 2종(thresholds 6곳 등록·등급 warn): `dropped_dbs`(보존
  영역 DB 수) · `stray_dbs`(허용 목록 외 DB 수 — 운영 DB·postgres·
  template* 제외). 기존 설치의 `flint_test`는 "레거시 공유 테스트 DB —
  DROP 뒤 purge" 안내로 처리한다. 조회 수단은 M1 착수 첫 태스크에서
  실증하고, 미지원 시 조용히 skip(v1.25.0 룰링 승계).
- footprint(v1.25.0 M2)에 엔진 재시작 횟수 표시 추가(ComposePsFn 관례의
  신규 seam).
- **엔진 메모리 측정 스파이크(L0)**: 전용 테스트 엔진에서 합성 부하 전후
  메모리를 재고 Go 런타임 상한(`GOMEMLIMIT`·`GOGC`) 후보값을 비교 →
  채택·기각 선언. 기본값 적용은 v1.30.0의 compose 내장과 함께.
- **기존 개발 기기 1회 정리 절차**(RUNBOOK 신설): `purge-dropped --yes`
  → 레거시 `flint_test` DROP → purge. 자동 실행 없음.

## 3. Ruling (사용자 결정 2026-11-23 포함)

- **테스트 엔진 자동 기동·띄워둠**(사용자 결정) — `go test`가 전용 엔진을
  자동으로 기동하고 종료 후에도 띄워둔다(무인 루프의 실DB 커버리지 보호).
  재부팅 뒤에는 기동하지 않고(`restart: no`) `make test-down`으로 회수.
- **런 종료 purge 포함** — 해소 출처가 전용 엔진 기본값일 때만(휘발 전용
  엔진이라 안전).
- **CI 정합** — job 환경 `FLINT_TEST_DSN` 명시 + 접속 실패는 fail +
  skip 0건 센티널.
- **lazy 보장** — 단위 테스트만 실행할 때는 엔진을 띄우지 않는다.
- **메모리 상한의 기본값 적용은 v1.30.0에 위임** — 이 버전은 측정·선언만.

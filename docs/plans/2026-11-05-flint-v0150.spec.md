- **날짜**: 2026-11-05 · **상태**: 기획 완료 · **오케스트레이터**: AI(무종점 루프 이터레이션 5 — 사용자 방향 "우아한 최적화·아키텍처·UX", PR 머지까지 자율)

## 1. 배경 — 이터레이션 5 조사 (2026-11-05, 실측 3건)

- **지표 오염 상속**: report zero_pct 49%가 v0.13.2 이전 프로브 오염
  (read 599건)을 누적 카운터(read_stats)로 영구 상속 — zero_near
  분해 지표의 분모가 오염됨. daily:* 카운터 설계와 누적 read_stats의
  불일치가 원인.
- **핫패스 왕복 과다**: read 1회의 계측이 본 쿼리 외 ~7-8왕복
  (read_stats RMW 2회[F3 이연 청산 대상]·daily RMW 2회·
  last_read_at upsert·BumpReads). 비간섭 원칙상 조용하지만
  레이턴시·DB 부하의 우아한 절감 여지.
- **지표→행동 루프 미폐쇄**: zero_near_pct는 report에만 존재 —
  진단(doctor)이 말해주지 않으면 사용자가 직접 해석해야 한다.
- exit 코드 분열(검증 오류 1 vs read 3, 72곳)은 확인 — 전량 스윕은
  차기 정리 이터레이션으로 이연(본판은 현행 계약 문서화만).

## 3. 요구사항

### R1 핫패스 계측 단일화
- `BumpReadStats(zeroHits, zeroNear bool, getKV, setKV)`로 시그니처
  확장 — read_stats를 **단일 읽기-수정-쓰기**로 calls/zero/zero_near
  전부 갱신. `BumpZeroNear` 제거(호출부·테스트 승계 정리). 기존
  getKV 전송 오류 시 미기록 계약(v0.14.0 fix) 불변.
- read 와이어링: bumpReadStatsToMeta가 분류(제로히트·근접)를 한 번에
  전달 — 제로히트 시 실행 순서 회피 주석·이중 RMW 제거.
- 계약 테스트: fake store 쿼리 카운트로 "eligible read 1회의 계측
  쿼리 수 ≤ 5"(종전 8) 고정. 정확 경계는 구현 시 계측 후 룰링.

### R2 zero 지표 기간화
- db 계측: `RecordReadUsage(ctx, zero bool, near bool) error` 신설 —
  daily JSON delta에 read:1(+ zero 시 read_zero:1, near 시
  read_zero_near:1)·last_read_at·PruneDaily 트리거 승계(기존
  RecordUsageCount 내부 공유). instrumentReads가 분류값을 전달.
- last_read_at upsert와 daily INSERT를 **2행 병합 upsert**(single
  statement)로 통합 — R1 왕복 절감에 기여.
- report: zero_pct·zero_near_pct를 --days 창 일별 합산 기반으로 전환
  (Σread_zero/Σread·Σread_near/Σread, 제로 분모 0). 누적 read_stats는
  status 등 기존 소비자·출력 불변. daily 키 부재 구버전 데이터는 0.

### R3 doctor zero_near 검사
- 신규 검사 `zero-near`: 최근 7일 daily 합산에서 read ≥ 10이고
  read_zero_near*100/read ≥ 30이면 warn — "어휘 불일치 의심 — 검색
  품질 개선 여지(지식은 존재·어휘 정리 필요)". 미만·표본 부족 ok.
  조회 실패 warn. fail 아님. 기존 검사·순서 불변(말미).

### R4 계약 문서화
- README exit 표(EN/KO): 0 성공 · 1 명령·검증 오류 · 2 저장소 장애
  (MapExit) · 3 read 인자 규칙 위반(구 계약 승계) — 현행 de-facto를
  명시. TUNING: 기간화 지표·doctor 임계(표본 10·30%)·계측 왕복 계약
  기록. PLAN §14 v0.15.0. 배지 release-v0.15.0(EN/KO).

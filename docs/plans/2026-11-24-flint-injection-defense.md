# flint 보안·주입 방어 명문화 — 영역 H (2026-11-24)

상태: draft
원천: 2026-11-24 전달·주입 레퍼런스 조사·마스터 인덱스
준수: K2(증거 가중치)·P2·살균 조크포인트·비목표(원격 쓰기 금지)·CLAUDE.md

## 1. 목표·위상

조사 확정: 메모리 오염은 세션 격리를 무력화하는 지속 공격 벡터이며,
방어의 중심은 세션 내 프롬프트 인젝션 방어가 아니라 **쓰기 경계**
(검증·provenance·살균)다. flint는 K2·pending 검수·쓰기 파이프라인·
살균을 이미 구현 — 본 영역은 이를 **명문화·회귀 테스트로 잠그는**
것이며 신규 메커니즘 개발이 아니다.

## 2. 스코프

1. **메모리 포이즈닝 회귀 테스트** — 합성 시나리오: 지시문 형태의
   지식행이 write→read 주입 경로에서 데이터 경계·pending 승격 회로·
   살균을 통과하는지 검증(현재 흐름이 차단하는 것을 테스트로 고정).
2. **쓰기 경계 방어 문서화** — K2 무검증 자동 승격 금지·pending 검수·
   선호/사실 분기(개정 vs 검증 경유)의 방어 위치를 계약 문서에 명문화.
3. **[flint] 경계의 위치 명시** — 데이터 경계 마킹은 보조 완화책이며
   강제 경계가 아님을 문서화(조사에서 확인된 OWASP 경고 반영) —
   진짜 방어는 쓰기 경계임을 명시.
4. **query-only 주입 시나리오** — 정상 상호작용만으로 악성 레코드가
   적립되는 경로가 있는지 점검(회상 실패 소구·echo 등 자동 적립
   입구의 입력 검증).

## 3. 원칙

- 신규 방어 메커니즘 금지 — 기존 구현의 명문화·테스트가 원칙.
  신규 메커니즘이 필요하다는 결론이 나면 별도 ADR.
- 테스트는 합성 시나리오만(개인 데이터 미사용).
- T2·결정론 유지 — 모델 훈련 의존 방어는 채택 불가(조사 확정).

## 4. 미결정 (착수 시 결정)

- 문서화 위치(contracts vs ADR·SECURITY 문서 신설 여부)

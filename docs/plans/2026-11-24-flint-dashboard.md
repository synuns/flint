## 1. 목표·위상

사람이 flint 내부를 한눈에 확인하는 계기판. flint는 에이전트 자율
관리 도구이므로 사람의 유일한 시야는 관측 표면이며, 본 기능은 지식
체계(영역 B)의 평가 기기다 — 독립 UI 기능이 아니다.

## 2. 결정 사항 (2026-11-24 사용자 확정)

- `flint report --serve` — localhost 한정 HTTP 서버. 명시 실행만·
  세션 흐름 무간섭·Ctrl-C 종료.
- 프론트는 `go:embed`로 단일 바이너리에 포장 — Go 템플릿·CSS·SVG·
  소량 vanilla JS. Node 런타임·별도 개발서버 없음.
- 정적 export(`--out`) 유지. serve는 **5번째 뷰** — report 4뷰
  (JSON·text·html·TUI)와 동일 Diagnose 원천 소비(단일 소스 원칙 승계).
  **템플릿 관계(2026-11-24 리뷰 룰링)**: 기존 html 대시보드 템플릿도
  5영역 골격으로 재편·공유한다(2벌 유지 아님 — 템플릿 1벌·동일
  Diagnose 원천). v1.32.0에 --out 재편과 회귀 테스트 포함.
- **serve 1급 표면 승격·단계적 일원화(2026-11-24 사용자 논의 확정)**:
  실시간·인터랙션은 serve 전용으로 개발하며 --out은 스냅샷 용도로
  한정한다(기능 패리티 미보장을 문서 명시). 실시간 대응은 serve 내
  JSON polling(기본)→SSE(필요 시)로 — vanilla JS·Node 불요. 실시간·
  인터랙션 수요가 실측되면 `--out`을 deprecated로 공고화(경고 문구·
  PLAN 갱신) 후 폐기 — 즉시 삭제는 리버서블성 상실로 보류. React가
  필요해지는 트리거는 실시간이 아니라 컴포넌트 복잡도이며, 그 시점에도
  서버는 Go 그대로(빌드 산출물만 embed 교체).
- 룰링 갱신: 시각화 내재화 폐기(2026-11-18)·PLAN §7 동적 서버 비목표는
  본 결정으로 해제. **React·차트 라이브러리 금지는 유지.**

## 3. 스코프

- 5영역 섹션: 지식 위생·회상 품질·토큰 경제·자율 튜닝·엔진 운영.
- 스키마 확장 불요 — 기존 계측(v1.19 이후 A 계열·rollup·tuning log)
  소비. thresholds에 포트 등 신규 키 등록.
- 보안: 루프백 바인드 한정·살균 조크포인트(render 단일 출구) 재사용·
  마스킹 계약(원격 sync의 url 마스킹 관례) 승계.

## 4. 개발 분리 (사용자 결정)

- **①에이전틱(무인 루프, 먼저)**: 서버·데이터 엔드포인트·embed
  인프라·HTML 골격(5영역 시맨틱 마크업·CSS 변수 훅)·계약 동반(
  커맨드 표·usage·docs-sync)·TDD. "기능은 다 되는데 못생긴" 상태까지.
- **②휴먼인루프(이후, 사용자와)**: 정보 위계·시각 언어·지표→차트
  매핑·인터랙션 — 스크린샷 반복 피드백. TBD 마킹.
- **경계 원칙**: 에이전트는 구조(시맨틱 HTML)와 훅(CSS 변수)만
  남긴다. 디자인은 구조 변경 없이 스타일 교체로 완결되어야 하며,
  디자인 착수 후에도 에이전틱 산출물은 유효해야 한다.

## 5. 비목표

- React·차트 라이브러리·원격 노출·다중 사용자·동적 데이터 쓰기
  (계기판은 읽기 전용)

## 6. 미결정 (착수 시 결정)

- serve 포트 기본값·thresholds 키 명명
- HTML 골격의 섹션 구성 상세(5영역 순서는 디자인 단계 확정)
- 엔드포인트 경로 체계·갱신 주기(poll vs 수동)

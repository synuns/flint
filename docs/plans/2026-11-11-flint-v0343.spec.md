## 1. 코드 구조 4건

### 1.1 (R11) doctor 체크 등록 4곳 분산 — 등록표 통합 [높음]

- 현황: 31종 체크 등록이 (a) DoctorChecks 6종 (b) doctorTailChecks 10종
  (c) runDoctor 하드코딩 append (d) runDoctorCheck switch (e) harness
  14종에 흩어짐. `--list-checks`(doctor.go:68)는 DoctorChecks 6종만
  출력 — 실제 16종(코어+tail) 중 10종이 발견 불가. v0.28.1 backup-key
  배선 누락 사고의 구조 원인이 잔존.
- 수정: 이름→checkFunc→체인 소속의 단일 등록표(슬라이스)로 통합.
  전체 실행 체인·`--check` 검증·`--list-checks`가 전부 등록표에서
  파생. 동질 테스트: 등록표 이름 집합 == 전체 체인 실행 집합 ==
  doctorTailChecks 허용 목록 집합(하니스·skill 계열 제외 명시).
- 부속: st==nil 판정이 체크마다 fail/warn으로 상이 — nil 가드 공통
  판정 헬퍼로 통일(tail 11종 warn·코어 4종 fail의 현 행동 유지를
  등록표 속성으로 명문화).

### 1.4 (R14) approve·done·backup 자체 연결 + 내부 중복 [높음]

- 현황: root가 전달한 Store를 무시하고 자체 db.NewRepo/Connect를
  여는 갱신 경로 3곳 — approve.go:21·done.go:430·backup dumpFn.
  v0.25.3 mcp 풀 누수 수정(defer st.Close)이 이 사각 연결에 미치지
  않아 장기 mcp 프로세스에서 호출마다 연결 누적.

- 부속(같은 파일 내 중복): quoteJSON(backup.go) ≡ quoteJSONApprove

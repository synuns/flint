## Ruling (G2 — 리서치 권안 채택)

- **GC 기본 full** — `--gc [--shallow] --yes`(플랜 usage 정합·희박 이벤트
  는 철저성 우선).
- **깊이 측정 O(1)** — `SELECT commit_order FROM dolt_log ORDER BY
  commit_order DESC LIMIT 1`(count(*) 아님).
- **db 크기 폴백 미채택** — pg_database_size 오류 시 조용히 skip(데이터
  디렉터리는 DSN 밖 — PLAN §4 원칙 3 대칭).
- **경고 등급 warn** — fail은 파손류 전용 관례.
- **임계 기본치** — dolt_log_depth_warn 10000·db_size_warn_mb 2048
  (보수적 초깃값·실측 인용 금지).
- **ANALYZE spike 양분 분기 사전 명시** — 지원 시 maintain --analyze
  채택·미지원 시 폐기 선언(플랜 §4 갱신) — 스파이크 결과와 무관하게
  진행.
- **audit_log 스파이크 = L0 문서 산물** — 스키마 설계안 DDL·diff 재현
  실증 쿼리·결론 노트(repo에는 결론만·실패 시 v2.0 G2 Ruling 입력).
- **스코프 v2.0.0 행 "v1.26.0 스파이크"→"v1.25.0" 정정 동반**(재교환
  잔여 표기 — 동일 커밋 갱신).

## 계약

### maintain --gc (M1)

- `flint maintain --gc [--shallow] --yes` — 사전 안내 1행(접속 단절
  명시)→`SELECT dolt_gc()`→Ping 재시도(상한 5회·1s 간격)→**5회 실패 시 안내+"reconnect failed" JSON·exit 1·meta 미기록(GC는 실행됐으나 완결 아님)**→성공 시 schema_version 재검증→meta `last_gc_at`·`last_gc_mode` 기록→JSON 결과.
- `--yes` 누락 시 exit 1(모드-조합 에러 — --reaffirm·--invalidate --ids·--recheck --conditions 공통 관례). 에이전트 배제(RUNBOOK만
  기재·skill/계약 문서 미기재 — sync 선례).
- usage·modeFlags·yesModes·FlagSpec 등록.

### doctor 경고 2종 (M1)

- `dolt_log_depth` — commit_order DESC LIMIT 1·임계 10000·안내
  "consider maintain --gc --yes (disconnects)".
- `db_size` — pg_database_size(current_database())·임계 2048MB·오류
  시 skip(조용히). 안내 "review backup retention — RUNBOOK".
- thresholds 2종 등록 **6곳**(store 구조체 필드·default 상수·DefaultThresholds·Parse case + wire thresholdMetas 대응행[오버라이드 로드 전제] + wire thresholds.go ApplyThresholdsFallback[unset 0 오탐 방지])+TUNING §2.

### RUNBOOK §10·§11 (M1)

- §10 가비지 컬렉션 — 접속 단절 계약·절차·실행 후 doctor/status 확인·
  엔진 자동 GC 우선 원칙·조용한 시간대 실행.
- §11 엔진 이미지 업그레이드 — backup→restore --drill→이미지 갱신→
  up -d→doctor 순서 고정.

### footprint (M2)

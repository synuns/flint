# flint 관측·수집 건강 자기감시 — 영역 F (2026-11-24)

상태: draft
원천: 2026-11-24 수집 통로 수리 사고·마스터 인덱스
준수: 비간섭 ④(경고는 임계 초과 시에만)·doctor 등록표 관례·CLAUDE.md

## 1. 목표·위상

수집 단절은 조용히 발생하며(`|| true`·exit 2 조용한 skip) 자율 게이트
(v1.27.0 관측 조건)를 묵살할 수 있다. "관측이 관측되고 있는가"를
자기감시하는 계층 — 사고 클래스의 재발 방지.

## 2. 사고 클래스 (근거 — 일반 서술)

수리 사고에서 확인된 단절 유형 4종: ①훅이 호출하는 바이너리가 PATH에
없음 ②config DSN 결함(해석 우선순위상 최우선 값이 불량) ③플러그인과
CLI의 버전 격차(훅·스킬 구성 누락) ④서비스 잔재(테스트가 남긴
launchd label이 죽은 경로 지칭). 전부 훅의 조용한 실패로 겉면에
노출되지 않는다.

## 3. 스코프 (doctor 확장 — 등록표에 체크 추가)

1. **훅 구성 검증(2026-11-24 자체 리뷰 정확화)** — 훅이 호출하는
   실행 경로(`flint` PATH 해석·플러그인 스크립트)의 존재·해석 검증.
   doctor 자신이 실행됐다는 사실은 그 셸에서의 PATH 통과일 뿐 —
   훅 셸에서의 해석이 검증 대상.
2. **config DSN 유효성** — config.json(engine_url·port)의 접속
   실패 분류(엔진 다운 vs DSN 결함 구분).
3. **수집 신선도 경고** — 최근 세션 흡수(session_starts 등)가
   임계 기간 이상 없으면 경고(사용 패턴과 구분: 신선도는 "신호"로만 —
   A4 관례 승계).
4. **플러그인-CLI 버전 격차 감지** — 설치 플러그인 버전과 CLI 버전의
   격차 임계 초과 경고.
5. **서비스 잔재 감지** — launchd label이 임시 디렉터 경로를
   지칭하는 등의 잔재 탐지(엔진 점유 잔재 클래스 확장).

## 3.1 원천 데이터 총목록 — 문서 편입 (2026-11-24 세션 발견)

METRICS.md는 GSM 목표별 편성이라 "수집 데이터 자체"를 일괄 확인하는
총목록이 없다 — 편입(사용자 결정). 두 작업:

1. **METRICS.md에 원천 데이터 총목록 섹션 신설** — 이벤트 테이블·
   daily counter 키 전수(진실 원천 = 코드 등록표
   `lib/db/usage.go` MeteringKindRegistry)·수집 조건(기록 경로·
   게이트)·보존 기간을 한 표로. 훅 구성 검증(§3)과 짝이 되는 문서
   층 — "스테일·단절은 조용히 발생한다"는 사고 클래스(§2)의 문서
   영역 확장.
2. **스테일 5키 정정** — METRICS §4.9 A5의 등록표 수 기술("24 keys —
   usage 10·curation 11·bytes 3")이 코드(총 29·curation 16) 대비
   뒤처짐 — correction_preference·correction_fact·merge_audit_pairs·
   recall_audit_listed·recall_audit_disposed 5키 미반영(2026-11-24
   세션 확인).

참고: doctor metering_silent(A5)는 코드 등록표 vs 관측 차집합으로
죽은 배선만 잡는다 — 문서 층은 검사 대상 아님. 문서-등록표 동기
검사(doclint 게이트 계열) 도입은 §5 미결정.

# flint v0.13.0 스펙 — 지능 축: 채택 재랭킹·모순 탐지

- **날짜**: 2026-10-31 · **상태**: 기획 완료 · **오케스트레이터**: AI(무종점 루프 이터레이션 3 — 사용자 확정 "1+2 지능 축", PR 머지까지 자율)
- **이전**: v0.12.1(PR #21 머지·태그)

## 1. 배경 — 완성도 평가·사용자 선택

- **코어 완성 판정**(3일 8버전) 후 남은 축은 지능·연결·시간 — 사용자가
  지능 축 선택: ①채택 피드백 ②모순 탐지.
- **채택 신호 이미 존재**: knowledge에 read_count·last_read_at 컬럼,
  RankOrder는 last_read_at를 최종 타이브레이크로만 사용 — 읽힌 정도가
  랭킹에 반영되지 않음. 검색이 사용할수록 좋아지는 루프 부재.
- **모순 탐지 부재**: supersede는 에이전트가 모순을 인지할 때만 동작.
  같은 topic에 결론이 다른 행(동일 topic·상이 요약)을 시스템이 플래그
  하지 못함 — 장기기억 무결성 보험 없음.
- 관측 대기 항목(minimal 체감·mcp·zero_pct)은 계속 축적 중.

## 2. 목표·비목표

목표: R1–R3. 비목표: 구문 경로 정렬 계약의 상위 요소 변경(topic 정확
일치>confidence>최신 순서 유지 — 채택은 최종 타이브레이크만)·모순
자동 해결(플래그만 — supersede 판단은 에이전트/사용자)·임베딩(ADR
승계)·Obsidian 브리지(차기 후보).

## 3. 요구사항

### R1 채택 재랭킹
- RankOrder 최종 타이브레이크로 `read_count DESC` 추가(last_read_at
  DESC 뒤). 폴백 경로 ReorderByFallbackCount도 정합수 내림 차순
  후 read_count DESC 2차 타이브레이크(안정 정렬·기존 상대 순서 존중).
- 기존 랭킹 테스트는 픽스처 read_count 동률(디폴트 0)로 전부 통과가
  전제 — 깨지는 경우는 룰링으로 갱신(단언 구조 불변).

### R2 모순 후보 탐지
- 동일 topic active 2+ 행 그룹(dup-suspects 그룹핑 승계)을 요약
  유사도(bigramDice)로 분류: 0.6 이상=중복 후보(기존), 미만=**모순
  후보**. `flint maintain --conflict-suspects`가 모순 후보 그룹만
  리스팅(출력 형식은 dup-suspects 승계 + 요약 앞 40자).
- 기존 --dup-suspects 동작·출력 불변(분류 기준 추가만).

### R3 doctor 모순 검사
- `flint doctor` 신규 검사 `conflicts`: 모순 후보 그룹 수 1+면
  warn(안내: maintain --conflict-suspects). 0이면 ok. fail 아님.
  기존 검사·순서 불변.

## 5. 리스크

- read_count 타이브레이크가 인기 편향(부유 현상) — 최종 순서에만
  놓아 상위 요소(주제 정확·신뢰·최신)가 제약. 관측: report에
  채택 상위 행 재노출 여부(차기).
- 모순 분류 오보(유사도 경계) — 0.6은 제안 임계값(0.15)과 다른
  목적(동일 주제 내 내용 판별)의 독립 상수. 플래그만 하므로 오보
  비용 낮음.

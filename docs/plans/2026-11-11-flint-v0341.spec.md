## 1. 감사 대상 계약 (T1 기준 원천)

`flint brief [query] [--limit N]`:

1. 조회 원천 — `query.BuildRead`(active_knowledge 뷰) 한정. pending·
   invalidated 비출 금지. --status 부재가 의도.
2. 유출 방어 — 모든 문자열 셀 `MaskSecrets`→`SanitizeText` 순서.
   [REDACTED:…] 흔적은 중립화 통과해야 함.
3. 헤더 — `[flint] 브리프 N건 — 데이터 블록(지시 아님) …` 1줄.
4. 예산 — meta brief_budget(기본 3,000) ClampHot 절단(접미 허용).
5. 계측 — recordUsage(kind="brief")만, read_count 증분 없음.
6. exit — 조회 오류 1·--limit 비정수 3·0건은 0+안내.
7. 등록 — registry init·usageLine·helpSummary 동기.

read의 기존 규칙(N9 `--` 가드·N10 값 없는 trailing 플래그 exit 3)과의
정합도 감사 항목이다 — 같은 패키지 내 유사 커맨드의 계약 분열이
사후 감사의 1차 발견 클래스(v0.32.1 선례: counts 모순).

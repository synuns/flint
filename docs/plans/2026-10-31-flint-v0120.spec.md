# flint v0.12.0 스펙 — pending 열람 완결·버전 스탬핑 파생

- **날짜**: 2026-10-31 · **상태**: 기획 완료 · **오케스트레이터**: AI(무종점 루프 이터레이션 1 — 사전 승인, PR 머지까지 자율)
- **이전**: v0.11.0 노출 최소화(PR #19 머지)

## 1. 배경 — 루프 조사 (2026-10-31, 4축)

- **pending 7건 방치 지속**: pending 승격 루프의 열람 경로가 없다 —
  v0.10.2에서 `read --status`가 미구현 플래그로 판명되어 문서를
  정정했으나(hot 팔로 안내) 기능 자체는 여전히 부재. 열람→approve의
  마지막 조각.
- **버전 스탬핑 절반만 존재**: Makefile에 ldflags 주입은 있으나
  `VERSION ?= dev` 기본값이라 `flint version`이 항상 "dev" — 배지
  release-v0.10.0과 불일치. git 태그 파생으로 해소.
- **부수 정리(운영·프로세스, 코드 밖)**: 운영 빌드는 `make build`로
  (go build 직접 사용이 스탬핑 누락 원인)·superlite 런 setup의
  `plan_tools adapter` 단계를 매 런 적용(그동안 누락 — probe 스킵 원인).
- 외부 레퍼런스(2026 메모리 프레임워크 관례): 모델 밖 저장+관련성
  주입은 flint와 정합 — cwd 관련성 랭킹은 유효 후보이나 minimal
  헤드라인 체제에서 실효성 낮아 이연 유지(룰링).

## 2. 목표·비목표

## 3. 요구사항

### R1 read --status
- `flint read [query] --status pending|active|invalidated` — 지정 시
  base 테이블 knowledge 조회 + `status = $` 조건·미지정 시 기존
  active_knowledge 뷰 경로 완전 불변(바이트·랭킹·출력).
- 결과는 기존 FormatRows 출력 승계(제로히트 제안·폴백은 --status
  경로에서 미발동 — 과거 시점 아닌 상태 필터는 재시도 대상 아님).
  필터 플래그(--tag 등)·--json·--fields 동일 적용. 무효 status 값
  exit 3(기존 검증 오류 계약 승계).

### R2 버전 파생
- Makefile `VERSION ?= git describe --tags --abbrev=0` 파생(태그
  부재 시 dev 폴백). `flint version` 출력 구조 불변.
- 배지 release-v0.10.0 → release-v0.12.0(EN/KO) — 이번 마이너
  전환 본질적 동반.

### R3 문서 동기화
- SKILL.md: pending 안내를 `flint read --status pending`(이제 실재)
  로 갱신·README: read --status 1줄·운영 빌드 make build 규칙 1줄·
  PLAN §14 v0.12.0 마일스톤.

## 5. 리스크

- --status 경로가 base 테이블 직접 조회로 살균(ADR-0006)·as-of를
  우회하는지 — 저장 살균 승계 가정 확인(테스트로 고정), as-of 플래그와
  --status 병용은 as-of 우선 안내(exit 3 아님 — 문서 1줄).

  가능하나 릴리스 태그 규칙(머지 후 태그)으로 해소.

# flint v1.11.0 스펙 — 지식화 파이프라인 1단계: 사용자 교정 채널

## 배경

사용자 제안(2026-11-19, docs/plans/2026-11-19-flint-knowledge-pipelines.md):
사람의 직접 교정이 최고 신뢰도 신호인데 현재는 이를 회고·적립하는
입구가 없다. 1단계는 케이스 매트릭스 최우선(사용자 직접 교정)만
B안(에이전트 계약 유도)으로 실증한다.

## 필수 요구사항

1. **source 등록표 확장**: validSources(hook|manual|mcp)에
   `correction` 추가 — 단일 소스 코드 등록표·문서 파생·동질 가드
   테스트(usage·에러 메시지·계량 키 자동 정합).
2. **correction 계약**: `flint write knowledge --source correction` —
   기본 confidence 0.7(사람 신호·hook 0.5와 구분)·태그 `correction`
   자동 부착·4연산(NOOP/UPDATE/ADD/supersede)·content_hash dedup·
   pending→approve 승격 회로 전부 기존 재사용(변경 없음).
3. **임계값**: thresholds 신규 2키 — `correction_confidence`(기본
   0.7)·`correction_daily_max`(기본 20, 빈도 상한 — 초과 시 조용히
   skip·경고 1행). 코드 기본값+meta 오버라이드 원칙.
4. **스킬 계약**: flint 스킬(~/.claude/skills/flint 및 repo
   SKILL.md가 아닌 개인 스킬은 repo 밖 — repo는 plugin
   flint-plugin/ 스킬만)에 교정 인지 지침 — "사용자 교정을 인지한
   에이전트는 즉시 flint write --source correction으로 적립(교정
   내용만 최소·추측 금지)". 비간섭 5원칙·전체 발언 캡처 금지 준수.
5. **계량**: dup_correction 계열 계량 키는 기존 패턴("dup_"+source)
   승계·적립→승격 전환율 관측은 키 설계 주석만(실측 인용 금지).
6. **문서**: HISTORY·계약행 TestVersion01110Milestone·README 배지·
   TUNING 2키·release-gate green.

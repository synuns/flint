## 1. 마일스톤

### M1 합성 회귀 세트 (영역 I — 공용 지반)

- 정답을 아는 합성 시드 → 질의 세트 실행 → read 결과가 정답에 도달하는
  지 판정(결정론 — 비LLM). 테스트 엔진 격리(FLINT_TEST_DSN)·
  seed.jsonl 관례 승계.
- abstention 채점 편입 — 소유하지 않은 질의에서 모른다고 말하는
  정확도(zero_hit_unowned_pct와 정합 — 단일 소스 METRICS 정의 대조).
- CI 편입 — make ci에서 합성 DB 회귀 실행(실행 시간 상한·표본 범위는
  착수 시 G2 확정).
- census·B5 센티넬·영역 H 시나리오는 이 지반의 소비자로 연결(독립
  구축 — 트리거 대기와 편성 의존 없음).
- **지표 노출** — 회귀 결과를 report·serve 대시보드의 지표로 노출
  (단일 소스 원칙 — METRICS 정의와 정합·영역 I §2.4 승계).

### M2 주입 방어 명문화 (영역 H — 신규 메커니즘 금지)

- 포이즈닝 회귀 테스트: 지시문 형태의 지식행이 write→read 주입 경로에서
  데이터 경계·pending 승격 회로·살균(SanitizeText)을 통과하는지 검증 —
  현재 흐름이 차단하는 것을 테스트로 고정.
- query-only 주입 시나리오: 정상 상호작용만으로 악성 레코드가 적립되는
  경로 점검(echo·재점검 등 자동 적립 입구의 입력 검증).
- 쓰기 경계·[flint] 경계(보조 완화책 명시)를 계약 문서에 명문화
  (contracts 계열 — SECURITY 문서 신설 여부는 Ruling).
- 신규 방어 메커니즘 금지 — 필요 결론 시 별도 ADR(원칙).

### M3 온보딩 smoke (영역 G)

- 설치 후 smoke 절차 — 연결→훅 감지→합성 쓰기→read→주입 확인의
  일련 검증을 단일 명령 또는 doctor 서브모드로 제공(Ruling: doctor
  모드·로컬 실행 우선).
- seed --demo 격리 승계(--reset 청소·운영 DB 오염 금지)·QUICKSTART
  실측 정비(doclint 실측 대조)·플러그인 갱신 안내(F 격차 체크 연결).
- 온보딩 안내는 사람·에이전트 양쪽 판독 가능(AX 원칙).

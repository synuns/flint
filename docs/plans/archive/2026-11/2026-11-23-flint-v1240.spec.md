## 계약

### 스키마 v19 (additive)

1. knowledge `kind text NULL`·`source_path text NULL` 2열(DEFAULT
   없는 NULL — 이전 바이너리 호환). content_hash 제외·kind 어휘
   검증(preference|fact·미지정 NULL).
2. `echo_candidates(id bigserial PK, ts timestamptz NOT NULL DEFAULT
   now(), candidate_id int NOT NULL, echo_id int NOT NULL, relation
   text NOT NULL, score double precision NOT NULL)` + 인덱스
   (candidate_id)·(ts) — write echo 산출 저장. **열 의미: echo_id = 신규
   write 행·candidate_id = 근사 이웃 행(응답 top-k와 동일). D1 소급
   산출(id→N일 내 supersede 표적 판정 쿼리·보고)은 관측 데이터 축적 후
   차기 이월 — 본 버전은 테이블 적립만(룰링).**
3. 스테이징: echo_candidates audit 계열·게이트 체인 v19.

### merge-audit (M)

- `maintain --merge-audit [--limit M]` — 활성 행 상호 multiset Dice ≥
  conflict_dup_threshold 쌍 리스팅(점수순)·스캔 상한 suggest_scan_cap·**사전 비용 추정 계약 — 쌍수 = min(cap,n)×(min(cap,n)−1)/2·µs/쌍 실측치로 사전 예산 공표(초과 시 cap 감소 안내·A6 p95 관측 동반)**·처분 안내 "dispose via maintain --merge/--supersede (approval required)"·카운터 merge_audit_pairs.

### 환류 일반화 (M)

- `maintain --recall-audit [--limit M]` — 같은 topic 무효화·superseded
  중 회상 이력 행 수 ≥ recall_audit_min_bad(신규 threshold·기본 2)인
  활성 행 리스팅·처분 승인제 위임·카운터 recall_audit_listed·
  recall_audit_disposed(D4).

### read --related / --why (M)

- `read --related N` — knowledge_links 양방향 UNION·relation 라벨 +
  역방향 표시·append(지식 행 후·interleave 금지)·source:"related"·
  --json related_hits·상한 5·대상 부재 exit 3.
- `read --why` — 근거 부록: 행별 토큰 tier(**인코딩: "topic_prefix×2+cover×1"
  형 토큰명×가중치 나열 — ReorderByTokenScore 내부 누적값 노출**)·RRF
  4신호(match·read_count·jamo·topic) 값·rank·기여 1/(k+rank)·zero-hit
  행 zero_reason+near_score. 기본 응답 불변.

### kind·source_path 쓰기 (M)

- write stdin 선택 `knowledge_kind`(preference|fact·미지정 NULL — kind 열 매핑)·`source_path`
  (경로 문자열·살균) — 둘 다 content_hash 제외·중복 재전송 멱등.
  **키 분리 규칙: 판별자 rec["kind"]="knowledge"는 불변 — 입력 kind는
  별도 입력 키(knowledge_kind — T2 확정)로 수용해 열에 매핑·판별자와
  입력을 혼동하지 않는다.**
- `--recheck N` — 기존 conditions 보고에 **source_path 일치 vault_files
  행의 content_changed_at 소거가 자동 수반**(--recheck 호출 시 항상 소거·--conditions 인자는 선택).
- D2: correction_preference·correction_fact 카운터(curation 그룹)·
  **적립 조건: source=="correction" write에서 kind값별 분기(전체 kind
  write 분포 아님).**

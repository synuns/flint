# flint v1.9.1 스펙 — 소형: TUI 저화면 적응·report 병렬화·tuning TUI

## 배경

v1.9.0(다중 기기) 직후에 처리할 소형 개선 묶음. 기존 백로그 3후보를
코드 근거로 재점검해 2건은 시행·1건(read TUI)은 제외한다.

근거(실측):
- **TUI 저화면**: pendingListHeight(lib/tui/pending.go:315)는 목록
  배분 = 높이−6, maintainListHeight(lib/tui/maintain.go:374)는 높이−7
  (하한 clamp 1). 12행 이하 터미널에서 크롬(키 안내·status·비대화
  안내·여백)이 화면 과반을 차지해 목록이 1~5행으로 쪼그라든다 —
  v1.5.2 적응형 TUI 잔여 과제.
- **report 수집**: RunReport(lib/ops/report.go:335-352)가
  collectDaily→collectCuration→collectStats→collectCounts→
  collectEffect를 순차 실행한다. 후속 4개는 상호 독립적인
  읽기·산출(각기 out의 상이한 필드)이라 병렬화 폭이 있다.
- **tuning**: `flint tuning`(lib/ops/tuning.go)은 임계값 조회·설정·
  리셋의 한 줄 JSON 인터페이스 — 이전에는 psql 직접 갱신이 필요했던
  관리 표면이다. huh 폼(setup 관례)으로 편집 진입장벽을 낮출 가치.
- **read TUI(제외)**: read는 에이전트 핫패스 JSON 표면
  (lib/cli/root.go:55 등록·즉시성 계약) — 대화 편집 가치가 없고
  적응형 진입 확대는 에이전트 경로 보장 원칙과 충돌한다. 비목표로
  확정.

## 필수 요구사항

1. **TUI 저화면(12행 이하) 크롬 최소화**: pending·maintain 화면이
   임계(12행) 미만에서 선택 크롬(비대화 안내·구분 여백·축약 가능한
   status)을 생략하고 목록 배분 공식이 줄어든 크롬을 반영한다.
   최소 화면(8행)에서도 목록 1행 이상·탈출(q/ESC) 안내는 유지.
   12행 이상에서는 현재 레이아웃 바이트 불변.
2. **report 수집 병렬화**: 독립 수집기(collectCuration·collectStats·
   collectCounts·collectEffect)의 조사 결과를 주석으로 남기고
   상호 독립 구간만 동시 실행(errgroup). out 필드 상호 배타성이
   깨지는 구간은 순차 유지. 출력 JSON 바이트 불변(기존 bytes·parity
   테스트 승계)·오류 선택은 순차 순서와 동일 우선순위로 결정적
   보존. 병렬화 전·후 wall-clock 실측(격리 DB·합성 시드) 기록.
3. **tuning --tui 옵트인**: `flint tuning --tui` — huh 폼(키 선택→
   값 편집→set/reset). 값 검증은 기존 실경로(loadThresholds→
   ParseThresholds — 파싱 폴백 시 거부 계약 승계). 적응형 진입
   없음: 무인자·기존 플래그 경로는 바이트 불변 위임(report의 cli
   재등록 패턴 승계). FLINT_NO_TUI·비터미널 exit 3 관례 승계.
   에이전트 기존 경로 불변(플래그 명시 전제).
4. **문서·버전**: v1.9.1 동기 — VERSION·README 배지·plugin.json·
   HISTORY·계약행·release-gate green. read TUI 제외 결정의 근거를
   HISTORY에 한 줄 기록.

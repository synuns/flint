# flint v1.15.0 스펙 — 배포·신뢰·마케팅 기반

## 배경

v1.3.0 백로그 이월 + 오픈소스 채택 장벽 해소. 기능 코드는 최소,
배포·문서·신뢰 아티팩트가 주체.

## 필수 요구사항

1. **Homebrew 배포**(룰링: formula→**cask** 교정 — goreleaser 2026 deprecation): brew tap 설치 경로 — formula 작성(release
   바이너리 다운로드·checksum 검증)·README 설치 절 갱신·
   tap 저장소 준비 지침(사용자 계정 레포 — 문서로 가이드).
2. **설치 경로 확장**:
   - `install.sh` 원라인 설치관(`curl -fsSL ... | sh`) — 플랫폼
     (darwin/linux·arch) 감지·release 자산 선택·다운로드 후
     checksum 자동 검증·설치 경로 결정(~/.local/bin 권장·PATH
     안내)·실행 취소 가능(문서화). 스크립트는 repo 심사 대상
     (check_personal·리뷰)·셸체크 관례 준수.
   - `go install github.com/synuns/flint/cmd/flint@latest` 경로
     문서화(Go 사용자용·버전 고정 주의 안내).
   - GitHub Releases 수동 다운로드 가이드(checksum 수동 검증
     명령 포함).
   - 요구사항 전제 명시: Doltgres 연결(기존 RUNBOOK 연계)·
     최소 Go 버전(바이너리는 무요구).
2b. **신뢰성 증명(Provenance·보안)**:
   - SECURITY.md — 취약점 보고 절차(연락 경로·대응 SLA 서술
     수준)·지원 버전 정책.
   - release 자산 무결성: checksums.txt(기존) 전량 생성 자동화
     확인 + 가능 시 cosign 서명 또는 SLSA provenance(attest
     workflow) — 도구 도입 비용 조사 후 문서화 우선·실행은
     가능 범위(무인 판정·근거 기록).
   - 배지 갱신: CI 상태·release·GoDoc(가능 시) — README 상단.
   - 신뢰 근거 문서: 비간섭 5원칙·로컬 단일 사용자·오프라인
     원칙·데이터 소유(사용자 DB) — "왜 안전한가" 절(README 또는
     docs/SECURITY-NOTES.md) — 과장 없이 구조적 근거만.
3. **README 국제화 정비**: EN README를 원전으로 KO 정합 재검토·
   설치·퀵스타트 절 보강(3커맨드 이내 첫 성공 경험)·아키텍처
   다이어그램 추가(텍스트 다이어그램).
4. **커뮤니티 기반**: CONTRIBUTING.md(기여 절차·make ci 로컬
   검증 안내)·ISSUE 템플릿(버그·기능)· 최소 CHANGELOG 링크.
5. **문서**: HISTORY·계약행 TestVersion01500Milestone·release-gate.

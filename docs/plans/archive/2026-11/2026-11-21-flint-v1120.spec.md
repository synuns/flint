# flint v1.12.0 스펙 — 지식화 파이프라인 2단계: 회상 실패 소구·반복 패턴

상태: draft

## 배경

사용자 제안 파이프라인(docs/plans/2026-11-19-flint-knowledge-pipelines.md)
케이스 매트릭스 2·3번째 — 회상 실패 소구(관측 신호 기반 격차 후보)와
반복 패턴(동일 쿼리 제로히트 누적)을 자동 입구로 추가한다.
1단계(v1.11.0 correction)와 같이 종점은 pending→approve 승격 회로.

## 필수 요구사항

1. **회상 실패 소구**: 관측 계층의 회상 실패 신호(bad_recall·
   owned_miss — 기존 관측 키 조사 후 활용)가 임계(retryBump 계열
   관례)에 도달하면 격차 후보 지식을 pending 적립 — 자동·confidence
   0.4(에이전트 자율 0.5 이하 관례)·태그 `gap-candidate`·source
   `hook` 계열 아닌 신규 등록 또는 기존 확장(설계에서 확정).
   내용은 "쿼리 X에 대해 회상 실패 N회 — 지식 격차 후보" 요약
   (쿼리 원문은 살균 경유·최대 길이 절단 관례).
2. **반복 패턴**: 동일(정규화) 쿼리 제로히트 N회(기본 3·thresholds
   `zero_hit_repeat_threshold`) 누적 시 동일 격차 후보 경로.
   정규화는 lib/query/suggest.go의 NFKC 재사용(suggestQuery는 절단만 — 리서치 정정).
3. **중복 방지**: 격차 후보는 content_hash로 중복 제거 — 동일 쿼리
   후보가 이미 pending/active면 업데이트(supersede 아님 — 카운트
   갱신 요약).
4. **임계값**: thresholds 2키(회상 실패 임계·제로히트 반복) — 코드
   기본값+meta 오버라이드.
5. **A안 조사(구현 없음)**: 하네스 훅 기반 교정 자동 감지(A안)의
   실현 가능성 조사 — Claude Code UserPromptSubmit 훅 등 가용 신호·
   프라이버시 제약 — RUNBOOK 부록으로 기록(v1.14 판정 자료).
6. **문서**: HISTORY·계약행 TestVersion01120Milestone·TUNING 2키·
   RUNBOOK 파이프라인 절 갱신·release-gate green.

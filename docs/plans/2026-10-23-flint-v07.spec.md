# flint v0.7 스펙 슬라이스 — 적립 자동화·실사용 재개 (2026-10-23 레퍼런스 조사 반영)

## 1. 적립 자동화

- 2계층 구조(조사 A1·A4·A10 준용): 레이어 1 보존 — PostCompact 훅이 컴팩트
  요약을 LLM 0비용으로 적립. 레이어 2 증류 — Stop/SessionStart 넛지로 Claude가
  자가 추출하여 knowledge화. 기록 계열 훅은 디스크에만 쓰고, 주입 계열 훅이
  회수를 담당한다(역할 분리 원칙).
- `flint compact` (PostCompact 훅 진입점): stdin JSON에서 compact_summary·
  session_id 파싱 → kind=session 적립(summary=compact_summary, --source hook).
  적립 성공 시 미증류 마커 생성(파일 — 플러그인 캐시, FLINT_CLAUDE_HOME 존중).
  어떤 실패에도 exit 0·조용히(비간섭).
- `flint nudge [--clear]`: Stop 훅 입력의 stop_hook_active=false 且 마커 존재 시
  hookSpecificOutput.additionalContext JSON으로 증류 지시 출력(지식 추출 →
  write knowledge --source hook → nudge --clear). SessionStart(plain stdout가
  컨텍스트에 주입됨)는 마커 존재 시 회수 안내만. --clear로 마커 소비. 무효
  입력·DB 부재 → exit 0 조용히. stop_hook_active·연속 cap 방어 필수(무한
  넛지 방지).
- 훅 배선 3종: plugin hooks에 PostCompact(`flint compact`)·Stop 넛지(`flint
  nudge`)·SessionStart 넛지(hot 훅과 별도 엔트리) 등록. timeout 2s 내 완결
  (SessionEnd 1.5s 공유 예산 교훈 — 훅 안에 DB 대기 없음).
- 증류 스킬(flint-plugin/skills/flint 확장): Mem0 4연산 준용 — 동일 NOOP(생략)·
  갱신 UPDATE(기존 항목 수정)·신규 ADD·모순 시 구 항목 invalidate(Zep invalidated-
  not-deleted 준수). 자동 적립 knowledge는 status=pending 시작(Letta
  review-before-applying 준용), 기존 approve로 확정.
- dup 대응: 신규 코드 없음 — 기존 dedup 파이프라인·report dup 카운트 재사용.
  병합·superseded 지침은 스킬 문서로(superseded 자동화는 v0.8 수명주기).

## 2. 실사용 재개

- 설정 파일: `UserConfigDir()/flint/config.json` {"dsn": "..."} — 우선순위
  --dsn 플래그 > FLINT_DSN env > 파일 > 기본값(localhost:5433). 재배치 env
  FLINT_CONFIG_DIR(gh GH_CONFIG_DIR·Dolt DOLT_ROOT_PATH 모델). 파손·빈값 →
  기본값 폴백. 표준 라이브러리만 사용(viper 불필요 — 조사 B3·B4).
- doctor 검사 6종 확장: 신규 "port" — `docker compose ps --format json`의
  Publishers 필드 파싱으로 (a) flint 컨테이너 실행 여부 (b) 5433 매핑 상태
  (c) 타 컨테이너 점유 보고 + 수정 명령 한 줄. docker 미가용 시 해당 검사는
  skip(fail 아님).
- 테스트 DSN 가드: real-DB 테스트에 testDSN(t) 헬퍼 도입 — FLINT_DSN 미설정 →
  t.Skip("FLINT_DSN not set; ..."), 설정됐는데 접속 실패 → t.Fatalf(konradreiche·
  storj·testcontainers 관례). 빌드 태그 안 씀(파일 단위 적용·오류 은폐 반론
  기각 — 조사 B7).
- `flint setup [--compose PATH(기본 ./docker-compose.yml)]`: compose up -d
  --wait --wait-timeout 60 → Migrate → 플러그인 설치 안내 순차. 대기 진단은
  pg_isready 의미론(거부=재시도·무응답=타임아웃 카운트·파라미터 오류=즉시
  실패). docker/compose 미설치 → fail + 수정 명령 한 줄(doctor 패턴 준용).
- Makefile `up`: `--wait --wait-timeout 60` 강화.

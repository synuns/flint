## 목표

사용자가 flint 표면(공지·doctor·setup)을 신뢰할 수 있는 기반 — 캐시 신선도·
버전 정합·바이너리 사용자 데모 경로. 스키마 변경 없음.

## Ruling (G2 — 리서치 권안 채택)

- **ETag 하위호환** — 구 캐시(필드 부재)는 ETag=""로 풀 fetch(자연 복구).
- **모순 검출기** — 캐시 latest < 현재 실행 버전 → 캐시 무시·즉시 재
  fetch. 등호는 정상. 네트워크 실패 시 조용히.
- **seed 격리 = 별도 DB(접미사 파생)** — 운영 DSN db명에 고정 접미사
  `_demo` 파생 + FLINT_DEMO_DSN 오버라이드. 신규 인프라 0.
- **go:embed = data 패키지 신설** — 모듈 루트 data/seed.jsonl을 embed
  원천 패키지로 추가(이동 아님 — Makefile 참조 양립).
- **자가 보고 meta 키** = `self_version_last:session-start`(값
  `version|RFC3339`) — **surface 단일(원본 §2B 회귀·RunSessionStart만 기록)**. 표면별 확장은 관측 후.
- **mcp-registry 오프라인** = "unverified (offline)" 표시(경고 아님).
- **plugin.json 버전 동기 전제** — bump_version.sh 기존 동기화가 보장.

## 계약

### M1 캐시 3원칙

1. updateCache에 `ETag string` 필드 추가. 구 캐시는 ETag="" 하위호환.
2. fetchReleaseMeta에 `If-None-Match` 헤더 + 304 처리(304=성공·캐시
   latest 승계·**checked_at=now로 갱신**). doctor FetchLatestVersionFn도 동일 경로 공유.
3. **모순 검출기** — maybeUpdateNotice 캐시 히트에서
   `compareVersions(c.Latest, cur) < 0` → 캐시 무시·즉시 재 fetch.
   실패 시 조용히.
4. **checked_at 노출** — noticeLine 확장 + report --text(기존 표면)에 확인 시점 노출.

### M2 seed --demo

- `flint seed --demo [--reset] [--yes]` — data 패키지 embed seed.jsonl을
  RunWrite 경유 적립(검증·dedup 단일 경로·재실행 멱등).
- 격리: 운영 DSN db명 + `_demo` 접미사 파생(FLINT_DEMO_DSN 오버라이드). **파생 실패(db명 부재·파싱 불가) 시 exit 3 + FLINT_DEMO_DSN 안내.**
- --reset: 고정 데모 식별자(전용 이름 + 소유 마커 meta)로만 삭제 대상
  식별·불일치 exit 3·--yes 필수.
- setup.go·setup_ux.go·QUICKSTART 문구를 `make seed`→`flint seed --demo`.

### M3 doctor checkVersions

- 등록표 1종 `{Name:"versions", Chain:"tail", OnStoreNil:"", Fn:
  checkVersions}` — 자기 버전·캐시 latest(+나이)·PATH flint
  (exec.LookPath)·mcp-registry 발행 버전(raw.githubusercontent.com synuns/flint plugin.json·ETag 동일 적용·설치 사본이 아닌 원격 발행) 나란히 표시.
- **자가 보고**: RunSessionStart에서 meta upsert(실패 조용히·
  RecordSessionStart와 동일 패턴). session_starts 스키마 불변.
- 오프라인: "unverified (offline)" 표시.

### thresholds

- `update_cache_age_h`(기본 72) — doctor versions 경고용. **metaKnownPrefixes에 self_version_last: 접두 등록(doctor 자기모순 방지).**

## 2. 5축 정의 (원천 D §2)

1. **표면별 접근성** — 첫 시도 성공 가능성(인자·플래그·출력 파싱)
2. **오류 계약** — exit 4종(0/1/2/3)·error 키·자가수정 유도
3. **usage·문서 표면** — usage 노출·SKILL.md·README 정확성
4. **주입·데이터 경계** — [flint] 접두·살균이 흐름을 막지 않는가
5. **실패 모드** — 엔진 다운 조용한 skip(exit 2)·훅 비차단·타임아웃

## 8. 교정 입구 권고 (A안 vs B안)

- **A안 하니스 훅 확장** — 교정 경계를 훅 계층에서 결정론 강제.
  근거(강점): correction_filter 전례로 확장 비용 낮음·위반 원천 차단.
  근거(약점): 하니스 종속(Claude Code 외 하니스 미흡 — §7 호환
  매트릭스상 훅 4종은 범용 불가)·훅 증가는 비간섭 리스크(v1.34.0
  UserPromptSubmit 기각 룰링과 긴장)·감사 발견이 문서·계약 성격이 다수.
- **B안 에이전트 계약 유도** — SKILL.md·exit 3 자가수정 메시지·문서
  정합으로 유도. 근거(강점): 감사 증거상 exit 3 메시지는 이미
  "다음 명령까지 제시" 수준(diff·approve·backup·index·done 구동 확인)·
  하니스 무관·신규 훅 0(비목표 승계와 정합). 근거(약점): 결정론 강제
  불가 — 계약 위반 에이전트는 막지 못함.
- **권고: B안 기본 + A안 한정 병행** — 전수 감사 결과 오류 계약의
  자가수정 유도성이 이미 기능하므로 교정 입구는 B안(계약 유도)을
  기본으로 하되, 결정론 강제가 검증된 영역(교정 필터·개인정보 가드)만
  A안 훅으로 유지·확장한다. v1.36.0 교정 입구 결정 시 발견 등록표
  유형별로 판정(§9) — 신규 훅 신설은 원칙 금지·기존 훅 확장만.

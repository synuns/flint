## 3. 요구사항

### R1 테스트 격리
- 신규 `FLINT_TEST_DSN`(기본 `postgresql://flint:flint-dev@localhost:5433/flint_test`).
  tests/regression·tests/e2e는 **이것만** 사용 — `FLINT_DSN`(운영)은 테스트에서 무시.
- 테스트 초기화(TestMain 또는 등가)가 flint_test 부재 시 생성 후 `Repo.Migrate`
  실행. Doltgres `CREATE DATABASE` 미지원 시 폴백: early-fail(v0.7 "DSN 미설정
  조기 실패" 원칙과 정합 — 조용한 스킵 아님).
- `make test`·`make ci` 통과, CI 워크플로(ci.yml) 변경 없이 통과.
- tests/regression/test_probe_\*.py(미참조 프로브 잔해, v06 wave0 산출물) 삭제.

### R2 실DB 정크 정리
- rv-\* 5건 `maintain --invalidate --ids 63,64,65,108,109 --yes`(가역).
  **R1 완료 후 코디네이터가 실행**(재오염 방지 순서). 무효화 사유 기록.

### R3 duplicate 응답 id 노출
- 단일 줄 duplicate 응답: `{"status":"duplicate","id":N}` — N은 기존 행
  knowledge.id. JSONL 집계형·exit 0·기존 필드 전부 불변(추가만).
- 목적: 에이전트가 "이미 #N에 있음"을 학습해 재제출 억제(77% dup의 루트).

### R4 maintain 중복 그룹 보고
- `flint maintain --dup-suspects [--limit M(기본 10)]`: active 중 동일 topic
  2건+ 그룹을 `{"status":"dup-suspects","groups":[{"topic":T,"ids":[…]}]}`
  한 줄 JSON으로 보고. 보고 전용·exit 0·판정은 에이전트(기존 원칙:
  SQL 자동 판정 금지). usage 라인 갱신 포함.

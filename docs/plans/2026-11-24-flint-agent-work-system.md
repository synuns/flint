## 1. 목표·위상

에이전트가 개발하면서 실수하는 패턴을 린트·게이트로 교정하는 전반
체계. 주석 계열(v1.26.3 commentlint·csweep·check_comments)의
일반화. 후속 개발(영역 B·A 등)의 속도·품질 인프라.

## 2. 현행 재고 (조사 결과 — 커버 현황)

- **이미 커버**: 주석(3종 검사)·문서-코드 드리프트(internal/doclint
  + release_gate)·개인 데이터·시크릿(check_personal.py)·YAML 문법.
- **부분 커버**: 표면 누락(usage·커맨드 표 가드 — 동작 깊이까지는
  미검증)·환각 API(컴파일 단만)·튜닝값 하드코딩(등록표 관례뿐).
- **커버 밖(신설 후보)**: 실패 테스트 삭제·t.Skip 증가 지름길(외부
  실증상 최고빈도 파괴 행동)·결정론 원칙 위반(외부 LLM SDK 유입 —
  T2 보호)·에러 삼킴(swallowed error)·부분 구현·조용한 범위 축소·
  검사 자체의 결함(메타 유형 — 신규 검사가 실제 실수를 못 잡는 경우).

## 3. pstack에서 채택할 장치

1. **규칙↔집행 쌍 표** — 규칙과 집행 장치를 표로 관리하고, "표에
   있는 규칙 = 실제 존재하는 집행 장치"를 검사로 강제. 집행 없는
   규칙은 재발로 간주해 상위 레벨(테스트·린트)로 격상.
2. **검사 실패 증명 원칙** — 신규 검사는 과거 실제 실수 커밋에서
   red임을 증명한 뒤 도입. (수리 사고류 인시던트가 증명 재료가 됨.)
3. **수리 사다리** — 아키텍처 > 타입/린트(에러 메시지가 수정처를
   이름) > 테스트 > 문서는 마지막(판단 문제에만).
4. **불변 규칙 ID 체계** — 규칙 삭제 시 빈틈을 명시하는 ID 관례.

## 4. 스코프 (신설 검사 후보 — 우선순위)

1. 테스트 삭제/스킵 감지 — CI에서 테스트 파일 삭제·Skip 수 증가·
   `-run` 필터 커밋 감지.
2. T2 보호 린트 — 외부 LLM SDK import 경로 감지(화이트리스트 방식).
3. vet·staticcheck·errcheck 상시화 + 면책 행 관례(이유·만료일).
4. 표면 계약 가드 확장 — 필수 플래그·exit 코드 표까지 검증
   (부분 구현·조용한 범위 축소 감지).
5. 구조화 실패 출력 — 파일:행·수정처 포함, 5줄 요약 구조(exit 3
   자가수정 관례와 정합).

## 5. 원칙

- 결정론만(비LLM in-loop) — 외부 조사도 "문서는 집행이 아니다"를
  확인: 규칙은 검사로 인코딩되어야 한다.
- 단일 소스 등록표 + 동질 가드(기존 관례 승계).
- 무인 루프에서 실패 메시지가 자가수정을 유도해야 한다.

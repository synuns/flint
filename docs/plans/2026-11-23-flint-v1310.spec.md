## 목표

Docker 없이 flint가 자기 전용 Doltgres 바이너리를 내려받아 직접 기동·
관리하는 경로를 제공한다. 컨테이너 런타임 설치·이미지 내려받기·VM 자원
의존을 제거하고, 배치 선택지 3종(네이티브·컨테이너·외부)을 코드 1벌로
유지한다. 스키마 변경 없음.

## 0. 문제

1. **기본 설치 경로의 전제가 무겁다**: 로컬 1인용 도구인데 설치가
   컨테이너 런타임을 요구한다 — 설치·상시 기동·유료 라이선스 환경·VM
   자원. 엔진은 단일 바이너리로 배포되므로 컨테이너는 필수가 아니다.
2. **엔진 가용성 = 기억 가용성**: 훅이 매 세션 엔진에 접속하고 실패는
   조용한 skip이므로, 엔진이 꺼져 있으면 그 세션의 기억이 사라진다.
   컨테이너 런타임의 기동 상태에 의존하는 구조가 이를 악화한다.
3. **분리 관리의 끝점**: v1.30.0의 외부 엔진 모드는 루프백의 다른 프로세스
   가 띄운 엔진을 전제로 한다. 같은 머신에서 컨테이너 없이 flint가 직접
   분리 운영할 경로가 없다.

## 1. 레퍼런스 조사 (2026-11-23)

- **엔진 실행 형태**: Doltgres는 서버 전용. 플래그 `-data-dir`(환경
  `DOLTGRES_DATA_DIR`)·`-config`·`-out-and-err`·`-version`. 설정 파일 키는
  `user.name`·`user.password`·`listener.host`·`listener.port`·`log_level`·
  `encode_logged_query`·`data_dir` (`doltgres -config-help`).
  https://www.doltgres.com/docs/introduction
- **바이너리 배포 형태**: 버전별 tarball은 중첩 경로(`<name>/bin/doltgres`
  + `licenses/`)이고 해제 후 바이너리는 100MB 길이이다. GitHub Releases에
  체크섬 자산이 없어 flint가 핀한다.
- **기존 내려받기 코드의 제약**: `flint update`의 다운로더는 재사용할 수
  없다 — 짧은 타임아웃이 본문 전체를 감싸고, 상한(128MiB)이 해제 후
  엔트리에도 적용되며, 압축 해제는 `flint` 이름의 엔트리만 찾는다
  (`lib/cli/update.go`).
- **프로세스 감독 관례**: macOS launchd 사용자 에이전트(RunAtLoad·
  KeepAlive — 로그인 시점 기동) · Linux systemd user 유닛(`enable --now`).
- **v1.30.0 스파이크 결과**(착수 조건): 결론 노트에서 이관.

## 2. 설계

- **배치 모델**: config.json `engine.mode = managed-container | native |
  external`(v1.30.0가 기록). 기존 설치에 값이 없으면 DSN 호스트로 추론해
  기록한다. 모드와 DSN이 어긋나면(예: native인데 `FLINT_DSN`이 다른 곳)
  doctor warn. `lib/engine`이 모드별 기동·상태·정지·버전을 인터페이스로
  캡슐화하고, 훅·MCP·플러그인은 DSN만 소비한다(무영향).
- **내려받기·검증**: 핀 버전·플랫폼별 해시를 flint 바이너리에 상수로
  내장한다(신뢰 뿌리는 flint 릴리스 서명). **전용 다운로더** — 디스크
  스트리밍·자체 크기 상한·중첩 경로에서 `bin/doltgres` 선택 → 해시 검증
  (불일치 거부) → `-version` 출력이 핀과 같은지 검증 → 원자 교체.
  `FLINT_HOME/engine/<version>/`에 전개하고 구버전 디렉터리는 보존한다
  (롤백). 실행 경로는 `engine/current` 심링크(핀 상승마다 서비스 재등록
  없음). 핀은 컨테이너 이미지 핀과 **4방 동치 가드**(compose 기본값·CI
  서비스 이미지·이미지 핀 상수·네이티브 핀 버전).
- **핀 불일치 동작**: 핀 상승 릴리스 뒤 `flint update`를 하면 엔진은
  구버전으로 남는다. 이 상태에서 **훅·MCP는 조용한 skip 계약(exit 2)을
  유지**하고(세션을 막지 않음), 사람 명령은 경고 + doctor `engine` fail로
  안내한다. 업그레이드는 사람 운영자 절차(RUNBOOK)다.
- **기동·감독 — 서비스 관리자 필수**: macOS launchd·Linux systemd user.
  `stop`은 등록 해제(`launchctl bootout`·`systemctl --user stop`), `start`은
  재등록·기동, `status`는 {registered, running, version}을 분리해 보고한다
  (KeepAlive 때문에 프로세스 종료는 재기동된다). **자동 기동은 서비스
  관리자의 로그인 시점 기동이 유일**하며, 훅·세션 시작은 엔진을 기동하지
  않는다(engine-ops §2 승계). 서비스 관리자가 없는 환경(WSL 비활성 등)은
  미지원 — doctor fail + systemd 활성화 안내.
- **자격증명 운반처 1곳**: 엔진 설정 파일 `FLINT_HOME/engine/config.yaml`
  (0600 — user·listener·data_dir). 서비스 등록 파일(plist·unit)에는 비밀값을
  두지 않고 0600으로 생성한다. v1.30.0의 `engine.env`는 비밀값 없는 변수만.
- **로그**: 기본 `log_level: info`·쿼리 미기록(`encode_logged_query:
  false`)·로그 파일 0600. Linux는 journald, macOS는 flint 소유 파일 +
  크기 경고(thresholds).
- **CLI 표면**: 멱등 `flint setup --engine <mode>` +
  `flint engine <status|start|stop>`. `restart`·`upgrade`는 제공하지 않는다
  (전자는 조합, 후자는 RUNBOOK 절차). `flint teardown`은 모드를 인식해
  서비스 등록·프로세스를 정리한다(데이터는 `--purge`로만).
- **업그레이드**(사람 운영자 — RUNBOOK §11을 모드 공통으로 재작성):
  backup → restore --drill → 데이터 디렉터리 스냅샷 → 새 핀 전개 → 기동 →
  doctor. 실패 시 구 디렉터리·구 핀으로 되돌린다.
- **모드 전환(container → native)**: 컨테이너 정지(볼륨 유지) → 같은 엔진
  버전으로 데이터 디렉터리 복사(4방 동치 전제) → 0700 → 네이티브 기동 →
  doctor에서 dolt_log 깊이·AS OF 결과가 같은지 확인. 실패 시 `engine.mode`
  원복 + 컨테이너 재기동. 컨테이너 볼륨 삭제는 네이티브에서 backup+drill을
  마친 뒤에만(사람 운영자).
- **doctor**: `db_size` 단일 소스 유지(v1.25.0 룰링 — 디렉터리 크기 폴백
  미채택), 데이터 디렉터리 크기는 info 표시. 네이티브 RSS seam 신설
  (`EngineStatsFn`은 docker 전용). `engine` 검사(등록·실행·버전·핀 정합).
- **CI**: Linux = slow+e2e(네이티브), macOS = "실내려받기·해시 검증 →
  `setup --engine native` → doctor → 세션 시작 주입" 1건 — 핀 상수 오류를
  잡는 의무 경로(바이너리 캐시).
- 문서: QUICKSTART·RUNBOOK·contracts/cli.md·ADR-0021(네이티브 엔진 모드)·
  PERF 합성 벤치(배치 모드별 디스크·메모리·기동 시간).

## 3. Ruling (사용자 결정 2026-11-23 포함)

- **새 설치의 기본 모드 — 네이티브는 옵트인**(사용자 결정): 기본 전환은
  별도 결정이다(루프에 소화 기간 관측 수단이 없다). 관리자 운영 기기에서
  무장애 운용과 doctor 경고 0을 확인한 뒤 재판정한다.
- **자격증명 — 기본 비밀번호 유지**(사용자 결정): ADR-0010 기본 DSN·
  Makefile·CI·QUICKSTART·스킬 계약과 ADR-0013 가정을 바꾸지 않는다. 루프백
  한정이 전제이다.
- **CLI 표면** — `flint engine status|start|stop` 3종(커맨드 표·usage·i18n
  등록 관례 문제일 뿐 기능 차이 없음).
- **모드 전환 수단** — 데이터 디렉터리 복사(v1.30.0 M4 실증이 조건 —
  이력을 잃는 백업·복원보다 우세). 미실증 시 이 안을 되올린다.
- **서비스 관리자 부재 환경** — 미지원 + 안내(수동 데몬화 표면을 만들지
  않는다).
- **로그 기본값·순환 주체** — 플랫폼 사실(launchd 무순환·journald 순환)에
  맞춘다.

## 3. 요구사항

### R1 did-you-mean — 제로히트 근접 후보
- `flint read <q>`에서 구문+폴백 모두 제로히트일 때만: active_knowledge
  전 스캔 후 질의와 topic·summary의 문자 bigram Dice 유사도 상위
  3건을 `"suggestions":[{"id":N,"topic":"…"}]` 필드로 출력(기존
  제로히트 출력·exit·필드 순서 불변, 필드 추가만). 유사도 0은 미출력.
- 유사도·정렬은 앱 사이드(Go) 순수 함수. 스캔 상한 없음(개인 규모
  수천 행 — 시퀀셜 수용 ADR 승계). 필터 플래그(--tag 등) 제로히트
  결과에도 동일 제안(제안은 필터 무관 전체 active 대상).

### R2 NFKC 정규화
- 매칭 비교 문자열(폴백 매칭 카운트·R1 유사도)에 질의·대상 양측
  Unicode NFKC 정규화 적용 — NFC/NFD·조합형 표기 차이 미스 차단.
- 구문 LIKE 경로 SQL·출력 불변(정규화는 Go 사이드 매칭에만).

### R3 자동 백업 사이드카
- `flint done`의 자동 백업(lazyDumpFile)이 덤프 기록 시 동일 경로에
  `.sha256` 사이드카를 남긴다(ADR-0006 규약 — 형식·검증은 기존
  integrity.go 승계). 수동 `flint backup` 경로 불변. 로테이션 짝
  삭제(rotate.go)는 기존 동작 승계로 자동 호환.

### R4 doctor 백업 신선도
- `flint doctor` 신규 검사 `backup-age`: meta last_backup이 72h+
  경과 시 warn(안내: done 훅·수동 backup), 미설정·DB 조회 실패 시
  warn. fail 아님(백업 부재가 flint 동작을 막지 않음). 기존 검사
  불변.

### R5 문서 동기화
- README.md·README.ko.md: read 설명에 근접 후보 제안 1줄·백업 무결성
  1줄. 배지 release-v0.9.7 → release-v0.10.0(EN/KO).
- docs/PLAN.md §14에 v0.10.0 마일스톤 기록.

# flint v0.8 스펙 슬라이스 — 시간여행 노출·수명주기 액션 (2026-10-23 레퍼런스 조사 반영)

## 1. 시간여행 노출

- 시점 스펙 3종 → 커밋 해시 정규화(조사 C1·C10): ISO 시각(2026-10-22T15:04)·
  상대(72h·7d — `d` 단위는 Go 확장 파싱)·커밋 해시 접두어. 정규화는 dolt_log
  ORDER BY date DESC에서 시각 직전 최신 커밋 채택, 이후 `AS OF '<hash>'`
  단일 경로. 자연어 스펙 배제, 무효 스펙 exit 3. 시간여행 단위는 커밋(미커밋
  워킹셋 제외)을 도움말에 명시.
- `flint read --as-of <스펙> [기존 인자]`: 기존 read 질의를 AS OF로 실행.
  결과에 as_of 해시·커밋 시각 포함. 뷰-컬럼 미호환 오류 시 기본 테이블 조회
  안내 한 줄(뷰+AS OF "현재 정의+과거 행" 규칙 준용, C3). 테이블 생성 이전
  시점은 "그 시점엔 아직 없습니다(첫 커밋: <시각>)" 오류(Snowflake 문구
  준용, C11). 리텐션 없음(첫 커밋까지, C12)을 문서화.
- `flint diff <from> <to> [--summary] [--data|--schema]`: 행 diff는
  dolt_commit_diff_knowledge 시스템 테이블(from_commit/to_commit WHERE +
  HASHOF — 제약 없음 우선, C6), diff_type added/modified/removed·from_X/to_Y
  컬럼(C5). 요약은 dolt_diff 커밋별 data_change/schema_change. 한 줄 JSON:
  {from, to, added, modified, removed, commits:[…]}.
- `flint status --as-of <스펙>`: 시점 스냅샷(pending/active/invalidated
  카운트 + as_of 해시·시각). 현재 전용 dirty 배지는 dolt_branches.dirty
  (as-of 결과에선 생략).
- audit 확장: `-n N`(기본 20 유지)·`--stat`(dolt_diff로 커밋별 테이블 변경
  요약)·시각 상대 포맷("3h ago" 자체 포맷 — log 시각 옵션 부재, C13).
- 스모크(실행 시 1회): 뷰 생성 이전 커밋의 AS OF 뷰 조회 실측(C 미검증 2) —
  동작 확정 후 오류 안내 문구 확정.

## 2. 수명주기 액션

- `maintain --stale` 출력 강화: 대상 목록(id·사유 stale|never_read)·요약 행
  "N to invalidate"(terraform 3단 구성 준용, D2). dry-run이 곧 기본값(기존
  보고 전용 승격).
- `maintain --invalidate-stale [--yes]`: 배치 무효화 — dry-run 기본(대상·
  요약만), 실행은 --yes 게이트만(대화 확인 프롬프트 없음 — 한 줄 JSON·크론
  친화 원칙 우선, D3 변형). 무효화=가역(기존 원칙 승계).
- `maintain --invalidate --ids "1,2,3"`: dry-run이 보여준 대상의 시점
  스냅샷 적용(plan-파일 패턴 — 재평가 drift 방지, D8). --ids와 --yes 병행
  필요(--ids 지정 시에도 실행 확정 의미로).
- superseded(schema v5, D4·D5): knowledge.superseded_by int NULL 추가
  (ALTER ADD COLUMN IF NOT EXISTS 멱등 — 기존 승격 체인 v4→v5 재사용).
  `maintain --supersede OLD --by NEW`: OLD status=invalidated·
  superseded_by=NEW·invalidated_at=NEW의 생성 시각(Zep t_invalid=t_valid
  준거). NEW 미존재·자기참조·이미 invalidated → exit 3/1. 역순 입력(신규가
  시간상 과거 정보) 규칙: 신규 우선 고정(SCD2 is_current 근사, D5).
- 증류 스킬 연계: SKILL.md UPDATE 연산에 supersede 절차(기존 항목 수정 대신
  신규 적립 + supersede) 추가 — 문구 재작성 아닌 원문 보존+링크(D4).
- 보존: invalidated 무기한 보존·회상 기본 스코프 active 유지(D6). 물리
  삭제 --purge는 §15 이연 유지.
- 트리거: launchd/크론 실행 가이드를 RUNBOOK·TUNING에 문서화(D7 — 저빈도
  권장). 세션 시작 자동 점검은 이연(훅 추가는 별도 판단).

## 3. 전역 제약

exit 0/1/2/3 · 한 줄 JSON · 비간섭(유지보수 경로 전부 오프라인 CLI 유지) ·
TDD(red→green→commit) · 기존 테스트 수정 금지 · 스키마 v5 승격 단 1컬럼
(superseded_by — 게이트는 기존 numeric >= 체인·Retry 재사용) · as-of 무효
스펙 exit 3 · 시간여행 질의는 항상 커밋 해시로 정규화(AS OF SYSTEM TIME
비의존, C 미검증 1 회피) · 유지보수 쓰기 경로(승격·supersede·배치)는
40001 Retry 동반(기존 원칙).

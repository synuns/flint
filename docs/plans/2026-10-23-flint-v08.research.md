# flint v0.8 레퍼런스 조사 (2026-10-23)

기둥 C(시간여행 노출)·D(수명주기 액션) 조사 결과. 출처 1차 우선.

## D. 수명주기 액션 — 8인사이트 (조사 완료)

1. **dry-run은 기본값이 아니라 "적용이 예외"인 구조가 표준.**
   출처: https://developer.hashicorp.com/terraform/cli/commands/plan ·
   https://git-scm.com/docs/git-clean
   ("The `plan` command alone does not actually carry out the proposed changes")
   적용: maintain --stale이 이미 plan 역할 — 무효화 실행은 별도 명시(--apply
   또는 --invalidate --yes). preview 기본 + force 게이트가 두 도구 공통 원칙.

2. **dry-run 출력 = 대상 목록 + 유형 구분 + 개수 요약 3단.**
   출처: terraform plan · kubectl diff 블로그
   적용: ①무효화 대상 목록(ID+사유: stale/미참조/superseded) ②요약 행
   ("Plan: N to invalidate"). 사유별 구분이 --stale 기존 보고와 자연 연결.

3. **확정 패턴 이원화: 대화형 확인 프롬프트 + 침묵 환경 --yes.**
   출처: terraform apply(-auto-approve) · git clean(-f)
   적용: 비TTY·크론은 --yes만. -f보다 의미 명확한 --yes 권장.

4. **superseded는 삭제 아닌 "만료 시각 = 신규 항목 유효 시작 시각".**
   출처: https://arxiv.org/html/2501.13956v1 ·
   https://www.getzep.com/blog/beyond-static-knowledge-graphs
   ("setting their t_invalid to the t_valid of the invalidating edge")
   적용: 갱신 지식 저장 시 구 항목 invalidated + superseded_by(신규 ID) +
   invalidated_at=신규 created_at. 문구 재작성 대신 원문 보존+링크로 단순화.

5. **이중시간 4타임스탬프보다 SCD2 근사(상태+is_current)로 충분.**
   출처: arXiv 2501.13956 · SCD2 관롄
   적용: status 열+타임스탬프가 is_current 근사 — 현재 조회=active만, 과거
   조회=시간여행(기둥 C)이 표준 질의 규칙. 역순 입력만 "신규 우선" 규칙 명시.

6. **invalidated 보존: 자동 만료가 아니라 "저장 강등", 삭제는 명시적.**
   출처: https://docs.weaviate.io/weaviate/manage-collections/multi-tenancy ·
   https://docs.pinecone.io/guides/data/delete-data · GDPR Art.5(1)(e)
   적용: invalidated 무기한 보존(가역성 유지)·회상 기본 스코프 active 유지·
   선택적 --purge(명시 하드 삭제)만 제공.

7. **자동화 트리거: "유휴 시점 비동기 정리"가 업계 표준.**
   출처: https://www.letta.com/blog/sleep-time-compute · launchd.plist
   적용: 3계층 — 수동 maintain · launchd/크론 저빈도 · flint 세션 시작 시
   백그라운드 경량 점검(건조 리포트 출력이 자연스러운 소비 시점).

8. **plan-파일 패턴: 승인을 계획 시점에 캡처해 drift 없이 적용.**
   출처: terraform -out 워크플로(공식 동작)
   적용: dry-run이 보여준 대상을 그대로 적용하는 경로(--invalidate --ids …
   또는 동일 조건 재지정)가 --yes의 필수 짝 — 재평가 drift 방지.

## C. 시간여행 노출 — 13인사이트 (조사 완료)

1. **AS OF는 커밋 해시·브랜치·HEAD^2·시간값 전부 수용.**
   출처: https://doltgres.com/docs/reference/version-control/querying-history
   적용: flint는 시점 스펙을 dolt_log에서 커밋 해시로 정규화 후 `AS OF '<hash>'`
   단일 경로만 사용.

2. **AS OF는 커밋만 본다 — 미커밋 워킹셋은 보이지 않음.**
   출처: 동일("always names a revision at a specific Dolt commit")
   적용: 도움말에 "마지막 커밋 시점" 명시. 현재 dirty 여부는 dolt_branches.dirty.

3. **뷰+AS OF 규칙: "현재 정의 + 과거 행" — v0.4 이전 커밋에서도 뷰 조회 근거.**
   출처: 동일("use the current definition of the view, but use rows from the
   tables as they existed at the revision provided")
   적용: 컬럼 미호환 오류 시 "기본 테이블 조회 안내" 힌트로 방어.

4. **과거 뷰 정의 자체는 `<db>/<hash>` 식별자로 접근.**
   출처: 동일("postgres://127.0.0.1:5432/mydb/<hash>" 읽기 전용)
   적용: flint diff의 스키마 비교 우회로. flint는 항상 해시 식별(브랜치 이름은
   워킹셋 포함이라 배제).

5. **DOLT_DIFF() 테이블 함수 — from/to_commit·diff_type(added/modified/
   removed)·from_X/to_Y 컬럼 확정. 인자는 리터럴만.**
   출처: https://doltgres.com/docs/reference/version-control/dolt-sql-functions
   적용: flint diff 코어. 단일 브랜치라 2인자 형식만.

6. **시스템 테이블 우선 권장 — dolt_commit_diff_<table>이 제약 없는 대안.**
   출처: 동일("prefer the system tables when possible, since they have less
   restrictions")
   적용: 행 상세는 dolt_commit_diff_knowledge + from_commit/to_commit WHERE +
   HASHOF. 단 컬럼 스키마는 현재 브랜치 기준 — 컬럼 변경 비교는 DOLT_DIFF()가
   정확.

7. **시스템 테이블 스키마 확정 — dolt_log 5컬럼(commit_hash, committer,
   email, date, message)·dolt_diff(data_change, schema_change, WORKING 표기)·
   dolt_branches.dirty.**
   출처: https://doltgres.com/docs/reference/version-control/dolt-system-tables
   적용: audit 확장(-n·--stat)·status dirty 배지. commit_order는 Doltgres
   미기술 → ORDER BY date DESC.

8. **뷰 정의는 dolt_schemas에 데이터와 함께 버전화.**
   출처: 동일
   적용: status --as-of에서 SHOW TABLES AS OF로 시점 스키마 구성 표시.

9. **dolt_history_<table> — 행 단위 전체 이력(삭제된 행 포함).**
   출처: querying-history
   적용: "이 기억이 언제 사라졌나" 단일 쿼리 — diff가 커버하면 별도 노출 불필요.

10. **git rev-parse의 시점 유연성(@{1 month ago} 등) 대비 flint는 3종 축소:
    ISO 시각·상대(72h/7d — d 단위 직접 확장)·해시 접두어. 자연어 배제.**
    출처: https://git-scm.com/docs/git-rev-parse
    적용: 시각 스펙은 dolt_log에서 직전 최신 커밋 해시로 정규화.

11. **Snowflake식 오류 문구 차용 — 생성 이전 시점 안내.**
    출처: https://docs.snowflake.com/en/sql-reference/constructs/at-before
    ("Time travel data is not available")
    적용: "그 시점엔 테이블이 아직 없습니다(첫 커밋: X)" 형식.

12. **BigQuery 리텐션 7일 상한 대비 Dolt는 커밋 그래프 무제한 — 차별점.**
    출처: https://docs.cloud.google.com/bigquery/docs/time-travel
    적용: "7일이 아니라 첫 커밋까지" 도움말·카피 명시.

13. **Dolt CLI 관례 — -n/--number·--stat·--oneline·diff --summary·--data/
    --schema. log에 시각 포맷 옵션 없음.**
    출처: https://www.dolthub.com/docs/cli-reference/cli
    적용: audit -n(기본 20)·--stat, diff --summary·--data/--schema 대응 —
    학습비용 0.

### C 미검증

- AS OF SYSTEM TIME 타임스탬프 문자열 형식(문서 예시 없음) — 해시 정규화로
  비의존 설계, 필요 시 1쿼리 스모크

  스모크 태스크
- dolt_log commit_order 존재 여부(Doltgres 미기술) — ORDER BY date DESC로 우회

# flint v0.14.0 스펙 — 제로히트 침묵 계약·zero_near 판별 계측

- **날짜**: 2026-11-04 · **상태**: 기획 완료 · **오케스트레이터**: AI(무종점 루프 이터레이션 4 — 사용자 방향 전환 반영, PR 머지까지 자율)
- **이전**: v0.13.2(PR #24 머지·태그)

## 1. 배경 — 사용자 방향 전환·사례 학습

- pickle-doctor RAG 사례 학습에서 도출한 갭: 제로히트의 원인을
  **"지식 부재"와 "검색 품질 문제"로 분리**해 계측할 수단이 없다.
- 1차 기획(제안 채택 추적)은 사용자 판단으로 폐기: flint는 **에이전트
  사용자에게 드러나지 않는 구조**여야 하며(v0.11.0 노출 최소화 승계),
  제로히트 시 did-you-mean 제안 라인을 출력하는 것 자체가 flint가
  에이전트에게 말을 거는 행위다. **제안이라는 절차를 두지 않는다.**
- 확정 방향: 제로히트는 **완전 침묵(무출력·exit 1)**. 판별은 에이전트에게
  보이지 않는 내부 스캔으로 — 기존 제안 스캔(bigramDice)을 출력 없이
  재사용해 근접 지식 존재 여부를 계측한다.

## 2. 목표·비목표

목표: R1–R3. 비목표: 제안 채택 체친(read_last_suggest — 폐기안)·
zero_near의 랭킹·임계값 반영(관측 먼저)·폴백 경로 변경(토큰 OR 재쿼리는
유지 — 데이터 출력이 아니라 결과 행이므로 침묨 계약과 무관)·
임베딩(ADR 승계)·lib/query 제안 함수 제거(SuggestSimilar·
BuildSuggestScan은 분류 엔진으로 승계 사용).

## 3. 요구사항

### R1 제로히트 침묵 계약
- `flint read` 제로히트 시 출력 완전 무(기존 결과 행 0 + 제안 라인
  폐지). exit 1 계약·다른 경로(히트·--status·--as-of) 출력 불변.
- suggestLine 타입·출력 블록·sanitize 루프 제거. `TestReadZeroHitSuggests`
  (v0.10.0)는 무출력 단언으로 재작성한다(룰링 — 계약 변경의 본질적
  동반. TestReadPhraseHitNoSuggest 등 나머지는 불변 통과 전제).

### R2 zero_near 판별 계측
- 제로히트·eligible 경로에서 기존 제안 스캔(BuildSuggestScan·
  SuggestSimilar, suggestMinScore 0.15)을 **출력 없이** 실행:
  근접 후보 1건 이상이면 `zero_near` 1회 증분 — "지식이 있을 법한데
  못 찾은" 제로히트. 후보 0건이면 미증분(지식 부재 신호).
- meta `read_stats` JSON에 `zero_near` 필드 추가(additive — 기존
  blobs 0 디폴트). `BumpZeroNear(getKV, setKV) error`가 증분한다.
- 실패는 조용히(§13 — bumpReadStatsToMeta 패턴).

### R3 report 노출·문서 정합
- reportOutput 말미 `zero_near_pct`(zero_near/calls 버림 정수%,
  제로 분모 0) 추가 — 기존 필드·순서 불변. zero_pct와 함께 보면
  부재 비율 = zero_pct − zero_near_pct로 분해된다.
- README EN/KO read 제안 문단(EN 152·KO 157) 침묵 계약 서술로 갱신,
  TUNING zero_near 소절(임계 0.15 재사용·해석 가이드), PLAN §14
  v0.14.0 마일스톤, 배지 release-v0.14.0(EN/KO).

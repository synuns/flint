# ADR-0013 — 위협 모델: 로컬 단일 사용자 (v0.28.0, 마일스톤 H①)

- 상태: 채택
- 일자: 2026-11-09
- 맥락: PLAN 마일스톤 H(전체 보안 점검·경화) — 보안 대상과 비대상을
  명시하지 않으면 경화가 무한 확산되거나 방어가 잘못된 경계에 배치된다.

## 배경

flint는 로컬 단일 사용자 도구다. 보안 설계의 모든 판단은 이 전제에서
파생한다. 이 ADR는 자산·경계·가정·비대상을 확정해 이후 경화 항목의
정당성 기준을 제공한다.

## 자산 (보호 대상)

1. **운영 DB 지식** — knowledge·sessions·project 표. 기밀성(개인 기록)·
   무결성(회상 신뢰 — 오염 지식은 에이전트 판단 오염).
2. **백업 파일** — 덤프는 운영 DB 전문의 사본이며 기기를 벗어나는
   경로(동기화·복사·업로드)가 가장 많은 아티팩트.
3. **config 키·DSN** — backup.key(age identity)·config.json의 DSN.
4. **주입 무결성** — [flint] 경계 마커(ADR-0006). 에이전트가 flint
   출력을 지시로 신뢰하므로, 저장 지식이 경계를 위조하면 저장된
   프롬프트 인젝션이 된다.

## 경계 (위협이 들어오는 면)

| 경계 | 위협 | 현행 방어 |
|---|---|---|
| 로컬 파일시스템 | 백업·config의 유출(동기화·복사 사고)·다른 로컬 계정의 읽기 | 0600/0700 권한·v0.28.0 age 암호화·마스킹 덤프 |
| 훅 stdin·지식 유입 경로 | 비밀 유입(compact 요약·임포트 파일)·제어 문자·[flint] 마커 위조 | SanitizeText·ScanSecrets(쓰기 시점+doctor 사후)·살균 후 게이트 |
| 업데이트 네트워크 | 위조 바이너리·다운로드 변조 | https 강제·sha256 checksums.txt 검증·verify-then-swap·128MiB 상한 |
| SQL 재생 매체(백업 파일) | 임의 SQL 실행 | sha256 사이드카 가드(위조 감지 시 중단)·마스킹 거부 |
| MCP·CLI 노출 | 파괴적 연산 무단 호출 | stdio/로컬 전제·파괴 연산은 명시적 커맨드만 |

## 가정 (방어가 성립하는 조건)

- 단일 사용자가 기기와 프로세스를 소유한다.
- 기기 자체는 침해되지 않는다(악성코드·다른 사용자의 권한 상승 없음).
- Doltgres는 로컬(localhost:5434)에서만 접근 가능하다.

## 명시적 비대상 (경화하지 않는 이유)

1. **기기 전체 탈취** — 키 파일과 암호문이 함께 탈취되므로 at-rest
   암호화로는 방어 불가. 전제 위반 사건이며 대응은 기기 수준(디스크
   암호화·원격 삭제)이다. backup.key가 백업과 함께 유출되지 않도록
   별도 보관하는 것은 사용자 운영 규칙(RUNBOOK)로 안내한다.
2. **로컬 권한 상승·악성 프로세스** — 같은 사용자로 동작하는 악성코드는
   flint 자체를 조작할 수 있다(설정·바이너리·DB). 로컬 신뢰 전제를
   깨는 위협은 flint 계층의 책임이 아니다.
3. **원격 DB 배치** — DSN이 원격을 가리키면 TLS·인증·네트워크 노출이
   새 위협면이 된다. flint는 로컬 전제로 설계됐다(기본 DSN localhost).
   원격 배치 요청 시 별도 ADR로 재검토한다.
4. **서비스 거부(로컬)** — 사용자 자신의 대량 유입·대형 쿼리는 악의
   공격이 아니다. 행 상한·임계값·doctor 경고로 운영 가능성을 지킨다.

## 귀결

- 경화 항목은 위 표의 경계에 배치된다. 비대상을 방어하려는 제안은
  이 ADR의 명시적 변경(또는 새 ADR)을 요구한다.
- 제3자 공유 산출물(스크린샷·GIF·진단 덤프)은 마스킹·합성 픽스처
  원칙(기존 방어 계층)을 따른다.
- 백업 암호화의 키 관리 책임과 분실 규칙은 RUNBOOK §4에 둔다.

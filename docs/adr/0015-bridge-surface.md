# ADR-0015 — 비로컬 AI(비서 등) 지원 방향: 브리지 채택, 원격 쓰기 금지

- 상태: 채택
- 일자: 2026-11-11
- 맥락: v0.34.0 — "MCP-native"가 모든 AI를 지원하는 것은 아니었다.
  지원 표면의 실제 전제를 명시하지 않으면 비로컬 AI 지원이 "가능한
  것처럼 보이는 구조"로 남는다.

## 배경 — flint 표면의 4가지 로컬 결합

1. **전송** — `flint mcp`는 stdio다. 클라이언트가 같은 기기에서 프로세스를
   spawn해야 한다. 클라우드 비서 AI는 이 전제를 성립시킬 수 없다.
2. **데이터** — Doltgres는 localhost:5434에 바인딩된다(ADR-0010).
3. **주입** — `[flint] hot` 주입은 로컬 하네스 훅(SessionStart·PostCompact)
   이 발화한다. 비로컬 AI에는 훅 표면이 없어 4단계 라이프사이클 중
   inject·stop 위생이 원천 소멸한다 — 비로컬 연결은 pull-only가 한계.
4. **신뢰** — ADR-0013이 "로컬 단일 사용자"를 명시적 전제로 경계를 짠다.
   원격 필자는 정의상 경계 너머의 신뢰 주체다.

즉 비서 AI를 "지원한다"는 주장은 현 구조에서 실현 불가능하며, 이는
결함이 아니라 살균·승인·감사라는 flint의 신뢰 모델이 로컬 전제로
설계된 결과다.

## 결정

1. **브리지(B) 채택** — 비로컬 AI는 사용자가 매개하는 수출면으로만
   접근한다. `flint brief [query]`가 마스킹된 읽기 전용 블록을 내고,
   사용자가 임의의 채팅(커넥터·봇 여부 무관)에 붙여넣어 전달한다.
2. **회수는 pending 인박스 한정** — 비로컬 AI의 산출물이 flint에 들어오는
   경로는 `flint write --status pending`·`flint import`뿐이며, 기존
   pending→approve 검수 회로(v0.32)를 그대로 통과한다. 신뢰된 필자는
   로컬 에이전트뿐이라는 원칙 유지.
3. **원격 쓰기 경로 개방 금지(상시)** — 원격 라이브 쓰기는 저장된
   지식의 신뢰 우물(ADR-0006 오염 방어·ADR-0013 경계)에 직접 붓는
   행위다. 어떤 형태(원격 MCP write·HTTP API·양방향 싱크)로도
   pending을 건너뛰는 쓰기는 만들지 않는다.
4. **브리프 유출 방어** — 기기 밖으로 나가는 모든 문자열은
   MaskSecrets(비밀 패턴 치환) + SanitizeText(제어 문자·[flint] 마커
   중립화)를 통과하고, 조회 원천은 active_knowledge 뷰로 한정한다
   (pending·invalidated 미검수 지식은 기기 밖으로 나가지 않는다).
5. **원격 MCP 표면(안건 C)은 재론 조건부 보류** — ① 브리지 실사용이
   관측으로 쌓이고 ② 접근 대상 비서가 원격 MCP 커넥터로 특정되며
   ③ 사용자가 자기 인프라(tailnet·터널·VPS) 노출을 감수할 때만
   재론한다. 재론 시 ADR-0013 개정(신규 경계 행)이 선행 조건이다.

## 결과

- README 포지셔닝은 "AI 코딩 에이전트"를 유지하되, 비로컬 AI는
  브리지로 안내한다. "MCP 지원"이 로컬 클라이언트 한정임을 명시한다.
- ADR-0013은 무변경 — 브리지는 로컬 도구의 수출면이지 서버 제품화가
  아니다(flint의 정체성: 단일 Go 바이너리 + 로컬 Doltgres).
- 원격 표면을 다루는 기여 제안은 이 ADR의 결정 3·5를 먼저 검증한다.

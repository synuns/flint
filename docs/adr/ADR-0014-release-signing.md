# ADR-0014 — 릴리스 서명: 키 기반 + GitHub Secrets (v0.31.0, 마일스톤 D)

- 상태: 채택(전환 모드 운영 — 키 등록 후 하드 검증)
- 일자: 2026-11-10
- 맥락: ADR-0013 경계 중 업데이트 네트워크의 잔여 위험 "같은 오리진
  체크섬 — GitHub 계정 침해 시 무력"(v0.28.0 ④ 수용 룰링)을 닫는다.

## 결정

cosign 키 기반 서명을 채택하고, 비밀키는 **GitHub Secrets**에, 공개키는
**바이너리 임베드**(lib/cli/cosign.pub, 빌드 시점 go:embed)로 둔다.

- **서명**: CI가 릴리스 시 checksums.txt에 `cosign sign-blob`
  (tlog-upload=false — Rekor 비의존·오프라인 검증 경로). .sig 자산으로
  업로드. 시크릿 미설정 시 스킵(전환 모드).
- **검증**: `flint update`가 checksums.txt 다운로드 후 .sig가 있으면
  임베드 공개키로 검증 — **Go 표준 라이브러리만 사용**(cosign v2.6
  기본 ECDSA P-256: SPKI PEM + SHA-256 + ASN.1 / ed25519: 순수 서명
  지원). 신규 의존 0.
- **순서**: 서명 검증이 sha256 체크섬 대조보다 앞선다 — 계정 침해자는
  위조 체크섬을 올릴 수 있어도 서명은 만들지 못한다.

## 대안 검토

- **keyless(OIDC/Fulcio)**: 사용자 설정 0이지만 신뢰 뿌리가 GitHub
  자신이라 계정 침해 위협에 추가 방어가 없고, flint update가 직접
  검증하려면 sigstore 인증서 체계 의존(거대 라이브러리)이 필요하다.
  출처 증명(provenance)만 남음 — 기각.
- **수동 로컬 서명**: 오리진 분리가 가장 강하나 배포 폐회(VERSION→태그
  →전부 자동) 원칙과 충돌 — 기각.

## 전환 모드와 하드 검증

1. **전환 모드(현재)**: 공개키 미임베드(빈 cosign.pub). .sig가 있어도
   경고 후 진행 — 서명 없는 구 릴리스와 키 등록 전 릴리스가 정상
   설치된다.
2. **하드 검증**: 관리자가 키를 등록하면(사용자 1회 5분, RUNBOOK §9)
   공개키를 임베드한 다음 릴리스부터 .sig 없음/불일치는 업데이트
   거부. 구 바이너리는 구 공개키로 검증하다 새 바이너리로 갱신된다.

## 키 운영(사용자 책임 — 최소화 설계)

- 최초 1회: 키쌍 생성 + 시크릿 등록(명령 1줄, RUNBOOK §9). 이후
  기억할 것 없음 — CI가 서명, flint가 검증.
- 롤링: 키 유출 시 새 키쌍 → 시크릿 재등록 → 공개키 커밋(새 바이너리).
  구 공개키를 임베드한 기존 설치는 새 키 서명을 하드 거부한다(의도된
  경보 — 신뢰 이전은 조용히 일어나지 않는다). 각 기기 1회
  `flint update --insecure-skip-signature`로 신규 키 바이너리로 이전
  하고 이후 자동 검증으로 복귀한다.
- 비밀키는 이 세션/에이전트가 절대 생성·취급하지 않는다(신뢰 뿌리
  오염 방지 — 사용자만 알아야 한다).

# ADR-0020: 엔진 이미지 핀·compose 프로젝트명 고정

- **상태**: 채택 (2026-11-24, v1.30.0)
- **배경**: v1.30.0 이전에는 compose 정의가 저장소 체크아웃 전제였고
  이미지 태그가 `:latest`였다(다이제스트 고정은 CI뿐). 바이너리↔엔진
  호환 조합이 정의되지 않았고, compose 프로젝트명이 실행 디렉터리에
  따라 달라져 라벨 기반 기존 설치 식별이 불가능했다. 바이너리만
  설치한 사용자는 git clone이 사실상 필수였다.
- **결정**:
  - 엔진 이미지는 **다이제스트로 핀**한다. 핀은 4방 동치 가드(바이너리
    내장 compose·CI 서비스 이미지·테스트 compose·코드 상수 — 문자열
    매칭)로 유지한다. 핀 갱신은 flint 릴리스를 통해서만 일어나며,
    사람 운영자가 compose 정의의 이미지를 수동으로 바꾸는 경로는
    폐지한다(RUNBOOK §11 절차 3).
  - compose 정의는 바이너리에 내장(`go:embed`)하고 최상위 `name: flint`
    로 **프로젝트명을 고정**한다. 컨테이너 식별은 라벨
    `com.docker.compose.project`의 정확 일치만 쓴다(이름 접두 일치는
    유사 이름을 오탐한다 — v1.29.0 스펙 승계).
  - 호스트 포트는 `${FLINT_PORT:-5434}` 변수로 주입한다(기본값은
    ADR-0010). 자동 배정 후보는 5434부터 순차 상향이며 **5499는
    제외**한다(v1.29.0 전용 테스트 엔진 예약 — ADR-0019 승계).
- **근거**: 바이너리 하나로 설치가 완결된다(저장소 없는 기기 지원),
  바이너리 버전과 엔진 버전이 릴리스 단위로 짝이 되어 호환 조합이
  명시된다. 다이제스트는 CI가 이미 동치로 쓰던 값이므로 신뢰 사슬이
  동일하다. 프로젝트명 고정은 기존 설치 보호(경고 후 정지, 수동 전환
  절차 안내)의 전제 조건이다.
- **단점**: 업스트림 버전업이 flint 릴리스 주기에 묶여 지연될 수
  있다. 다이제스트 4방 동치는 유지 비용이며, 핀이 낡으면 업스트림
  보안 수정 반영이 늦어진다. 다른 프로젝트명으로 운영 중인 기존
  엔진은 자동 이전되지 않고 사람 운영자의 수동 전환 절차(RUNBOOK
  §11)를 거쳐야 한다.

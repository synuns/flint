# flint 기록 기준 카탈로그 — 무엇을 저장하고 무엇을 저장하지 않는가

- **날짜**: 2026-10-22
- **상태**: v0.4 기획 확정 (콘텐츠 정책)
- **적용 대상**: `flint write`를 호출하는 모든 에이전트(CLI·MCP 공통)

---

## 1. 기록 유형 카탈로그 (knowledge)

기록할 가치가 있는 정보 7종 — 우선순위 순:

| # | 유형 | 정의 | 예 | confidence 기본 |
|---|---|---|---|---|
| 1 | **확정 결정** | 되돌림 비용이 있는 선택 + 그 이유 | "백업은 pg_dump 실패로 자체 SQL덤프(ADR-0002)" | 0.9 |
| 2 | **사용자 교정** | 사용자가 내 접근을 수정한 사실 + 수정 후 규칙 | "리스트는 5개 상한이다" | 0.95 |
| 3 | **사용자 선호** | 반복 적용되는 취향·제약 | "출력은 한국어, preamble 금지" | 0.9 |
| 4 | **환경 제약** | 이 머신·이 저장소에서만 참인 사실 | "호스트 5432는 로컬 Postgres 선점(ADR-0001)" | 0.9 |
| 5 | **실패 학습** | 시도→실패→원인 (되풀이 방지) | "pg_dump는 REPEATABLE READ 미지원으로 실패" | 0.85 |
| 6 | **프로젝트 상태** | 진행 중 작업의 현재 위치·다음 단계 | "v0.3 mcp 완료, 릴리스 대기" | 0.85 |
| 7 | **외부 사실** | 재조회 비용이 큰 참조 정보 | "Doltgres 1.4.0의 dolt_backup 미지원" | 0.8 |

session(kind=session)은 세션 단위 요약, project(kind=project)는 프로젝트 생애주기 상태 전용.

## 2. 안티골 — 저장 금지 5종

1. **코드·구현 자체** — git이 소스 오브 트루스. "무엇을" 아닌 "왜"만.
2. **일회성 산출물** — 재사용 없는 명령 출력·중간 계산·임시 파일 내용.
3. **Obsidian 원본 복제** — §1 단방향 흐름 위반. 인덱스·요약만.
4. **민감정보** — 자격증명·토큰·비밀번호(백업 파일로 새어나감).
5. **추측·미검증 가설** — confidence<0.8로 쓰되 내용 자체가 검증 불가능한 소문이면 쓰지 않는다.

## 3. 단위·명명 규칙

- **1레코드 = 1사실**: 독립적으로 무효화 가능한 최소 단위. 두 사실이 함께만 의미 있으면 병합, 아니면 분리.
- **summary**: 한 줄(80자 절단 전에 의미 완결). "X는 Y다" 형태 — "Y에 대해" 금지.
- **topic**: 주제명(명사구, 검색 키워드 관점). "flint 저장소"처럼 재사용되는 안정 명칭.
- **entity**: 사실의 주체(시스템·프로젝트·사용자 중 하나, 소문자).

## 4. 어휘표 (tags·domain 표준)

- **domain**: `main`(기본)·`infra`(환경·도구)·`preference`(사용자 선호) — 3종만.
- **tags** 소관(필요시 확장하되 본 표에 먼저 추가):
  `adr`(결정 기록)·`correction`(교정)·`failure`(실패 학습)·`env`(환경)·`process`(작업 방식)·`contract`(계약·인터페이스)

## 5. confidence 의미론

| 구간 | 의미 |
|---|---|
| 0.9~1.0 | 문서·사용자 발언·실측 근거 |
| 0.8~0.89 | 세션에서 확정했으나 단일 출처 |
| <0.8 | 추정 → **pending**(검수 게이트 진입, 승인 대기) |

## 6. 수명 규칙 (valid_at·invalid_at)

- **환경 제약(유형 4)**: 환경이 바뀌면 사망하는 사실 — invalid_at 후보 1순위.
- **무효화는 `maintain --invalidate --reason` 전용** — write 경로에서 갱신 금지(부록 계약).
- 프로젝트 완료(project status=done)는 레코드 무효화가 아니라 상태 갱신.

## 7. 시딩 정합

`data/seed.jsonl`의 모든 레코드는 본 카탈로그의 유형·어휘표를 따른다(검증: `docs/tuning_test.go`와 동일 grep 방식 — v0.4에서 `flint write` 시 어휘 경고로 승격).
